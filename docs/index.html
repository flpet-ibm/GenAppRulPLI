GenApp General Insurance Application (PL/I on CICS, Db2 and VSAM) – Architect's Wiki

A guide to the PL/I implementation of the GenApp general insurance application on z/OS. It covers the CICS 3270 menus, the business-logic orchestrators, the Db2 and VSAM back ends, the batch reporting and export programs, and the shared logging, setup and statistics utilities.

Application Documentation
Overview
Application Overview High-level introduction to the GenApp general insurance application. It covers the customer and policy domains (endowment, house, motor, commercial, claim), the online and batch entry points, and how the program families fit together. Program Catalog and Naming Conventions Index of all PL/I programs, grouped by function (inquiry, add, update, delete, test menus, batch, utilities). It explains the naming scheme: the IC/AC/UC/DC prefixes for customer operations, the IP/AP/UP/DP prefixes for policy operations, and the -01/-DB/-VS suffixes for business-logic, Db2 and VSAM programs.
Architecture
Layered Architecture and Call Flow Describes the layering of the application. 3270 menu programs call business-logic orchestrators (LGxxOL01 and LGxxUS01). These LINK to Db2 back ends, which in turn LINK to VSAM synchronisation programs. The page covers COMMAREA conventions, request identifiers and return-code handling across layers. Db2 Data Access Programs The Db2 back-end programs that read and modify the CUSTOMER, CUSTOMER_SECURE, POLICY and policy-type tables (ENDOWMENT, HOUSE, MOTOR, COMMERCIAL, CLAIM). Covers SQL usage, cursors, foreign-key cascades, SQLCODE-to-return-code handling and the LINKs to the VSAM programs. VSAM KSDS Data Access Programs The VSAM back-end programs for the KSDSCUST customer file and the KSDSPOLY policy file. They cover read, write, rewrite and delete operations, key construction, generic GTEQ browsing, and the abend codes and return codes used on failure.
Customer Management
Customer Inquiry The customer lookup flow. The LGICUS01 business-logic entry point calls LGICDB01 for Db2 retrieval. LGICVS01 returns a valid random customer number from the VSAM file and the GENACNTL range queue. Customer Creation and Security Registration How new customers are onboarded. This covers the Db2 insert with a customer number from the named counter, the VSAM record write, and the creation of the CUSTOMER_SECURE record. Customer Update The customer update chain. The LGUCUS01 orchestrator validates the request and links to LGUCDB01, which updates Db2. LGUCDB01 then calls LGUCVS01 to keep the VSAM customer file synchronised.
Policy Management
Policy Inquiry The policy and claim inquiry flow. LGIPOL01 is the business-logic entry point and LGIPDB01 retrieves data from Db2 for each policy type, claims, and multi-record lookups. LGIPVS01 does the generic key browse on the VSAM policy file. Policy Add The new-policy flow. LGAPOL01 orchestrates, optionally calling the ODM business-rules program LGAPBR01. LGAPDB01 inserts into Db2 and LGAPVS01 persists the policy record to the VSAM KSDS. Policy Update The policy update chain. LGUPOL01 validates and dispatches the request. LGUPDB01 uses a cursor and optimistic concurrency on the timestamp to update the Db2 tables. LGUPVS01 rewrites the VSAM policy record. Policy Delete The policy deletion chain. LGDPOL01 dispatches by policy type and LGDPDB01 deletes from the Db2 POLICY table, with child rows removed by foreign-key cascade. LGDPVS01 removes the matching record from the VSAM policy file.
Online User Interface (3270 Menus)
Customer Menu (LGTESTC1, SSC1) The 3270 customer menu for inquiring about, adding and updating customers. It delegates to the customer business services and maintains the GENACNTL customer-range queue. Motor and Endowment Policy Menus The 3270 menu programs for motor policies (LGTESTP1, map SSMAPP1) and endowment policies (LGTESTP2). They cover inquire, add, delete and update, plus pseudo-conversational handling and PF3 exit. House and Commercial Policy Menus The 3270 menu programs for house policies (LGTESTP3, SSP3) and commercial policies (LGTESTP4, SSP4). They cover the request codes used, the back-end services called, rollback on failure and screen handling.
Batch Processing
Batch Customer Reporting The non-CICS batch programs that produce customer detail lines. LGBATCH drives the report from an input file of customer numbers. LGBATCHF formats each report line. LGBATDB2 is a single-customer test driver. Motor Policy Export The batch program LGMOTOUT. It exports the GENASA1.MOTOR table to a sequential flat file through a read-only Db2 cursor and sets a return code for the calling job.
Operations and Shared Services
Shared Error and Message Logging (LGSTSQ) The common logging utility that writes to the CSMT transient data queue and to GENAxxxx temporary storage queues. It is called by the orchestrator, Db2 and VSAM programs to record diagnostics. Environment Setup and Reset (LGSETUP) Resetting the demo environment. This covers clearing the temporary storage queues, rebuilding the control queue and customer range, recreating the customer-number named counter, and zeroing the statistics counters. Transaction Statistics Collection Monitoring of transaction volumes. LGASTAT1 is the event-processing adapter that increments named counters per request type and outcome. LGWEBST5 periodically aggregates the counters and computes deltas into temporary storage queues.
