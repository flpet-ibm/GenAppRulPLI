House and Commercial Policy Menus

This page documents the two 3270 menu programs that drive house and commercial policy maintenance in the GenApp PL/I application:

  • LGTESTP3 runs as transaction SSP3 and uses BMS map SSMAPP3. It handles house policies.
  • LGTESTP4 runs as transaction SSP4 and uses BMS map SSMAPP4. It handles commercial policies.

Both programs are pseudo-conversational CICS front ends. They do no database access of their own. Each one reads a single-character option from the screen and builds a request in the shared 32,500-byte COMMAREA. It then calls a back-end orchestrator (LGIPOL01, LGAPOL01, LGDPOL01 or LGUPOL01) with EXEC CICS LINK. Finally it shows the result or an error message on the same screen. This page covers the request codes, the back-end services, the rollback behaviour and the screen handling.

1. Overview

1.1 Purpose

Aspect House menu (LGTESTP3) Commercial menu (LGTESTP4)
Transaction SSP3 SSP4
BMS map / mapset SSMAPP3 / SSMAP SSMAPP4 / SSMAP
Operations Inquire (1), Add (2), Delete (3), Update (4) Inquire (1), Add (2), Delete (3)

Message field ERP3FLDO (CHAR 40) ERP4FLDO (CHAR 40)
Exit text “Transaction ended” “Transaction ended”

1.2 Key Characteristics

  • Pseudo-conversational. Each successful or error-handled path ends with EXEC CICS RETURN TRANSID(...) COMMAREA(COMM_AREA).
  • Reentrant. Both programs are declared Options(Main,Reentrant). State lives in the COMMAREA, not in static storage.
  • Request-code driven. CA_REQUEST_ID tells the back-end which operation to run.
  • Return-code driven. After every LINK, the programs test CA_RETURN_CODE. A value above 0 means failure.
  • Rollback on failure. A failed add or delete issues EXEC CICS SYNCPOINT ROLLBACK.
  • Clean reset after errors. ERROR_OUT blanks the maps and the COMMAREA before it returns.

3. Request Codes and Back-End Services

CA_REQUEST_ID is a six-character code. The first two characters are a sequence number (01, 02, 03 or 05). The next one is the operation: Inquire, Add, Delete or Update. The last three name the policy type (HOU or COM).

4. Screen Handling

4.1 Initial Display

On first entry (EIBCALEN = 0), each program points COMM_AREA_PTR at BASE_COMM_AREA. It blanks the output map and the COMMAREA request area. It then sets the numeric display fields to zeros and sends the map with ERASE.

PLI 
IF EIBCALEN = 0 THEN DO;
   COMM_AREA_PTR = ADDR(BASE_COMM_AREA);
   SSMAPP3O = '';
   CA_REQUEST_ID = '';
   CA_RETURN_CODE = 0;
   CA_CUSTOMER_NUM = 0;
   CA_REQUEST_INITIALISER = '';
   ENP3CNOO = '0000000000';
   ENP3PNOO = '0000000000';
   ENP3VALO = '00000000';
   ENP3BEDO = '000';
   EXEC CICS SEND MAP('SSMAPP3') MAPSET('SSMAP') ERASE;
END;

This is an illustrative sketch of the logic described. The LGTESTP4 version sets ENP4CNOO and ENP4PNOO to ten zeros and blanks the peril, premium and status fields.

4.2 Receive and Dispatch

Handlers are registered before each RECEIVE MAP. A SELECT on the option field then picks the branch.

PLI 
A_GAIN:
   EXEC CICS HANDLE AID CLEAR(CLEARIT) PF3(ENDIT);
   EXEC CICS HANDLE CONDITION MAPFAIL(ENDIT);
   EXEC CICS RECEIVE MAP('SSMAPP3') INTO(SSMAPP3I) MAPSET('SSMAP');

   SELECT (ENP3OPTO);
      WHEN ('1') ...   /* inquire */
      WHEN ('2') ...   /* add     */
      WHEN ('3') ...   /* delete  */
      WHEN ('4') ...   /* update  */
      OTHERWISE ...    /* invalid */
   END;

5.2 Inquire (Option 1)

The program sets CA_REQUEST_ID to 01IHOU and copies the customer and policy numbers from the output view of the map. It then links to LGIPOL01. A return code above 0 goes to NO_DATA. Otherwise the house details are moved to the screen and the map is sent.

PLI 
WHEN ('1') DO;
   CA_REQUEST_ID   = '01IHOU';
   CA_CUSTOMER_NUM = ENP3CNOO;
   CA_POLICY_NUM   = ENP3PNOO;
   EXEC CICS LINK PROGRAM('LGIPOL01')
        COMMAREA(COMM_AREA) LENGTH(32500);
   IF CA_RETURN_CODE > 0 THEN GO TO NO_DATA;
   ENP3IDAI = CA_ISSUE_DATE;
   ENP3EDAI = CA_EXPIRY_DATE;
   /* ... property type, bedrooms, value, name, number, postcode ... */
   EXEC CICS SEND MAP('SSMAPP3') FROM(SSMAPP3O) MAPSET('SSMAP');
   GO TO ENDIT_STARTIT;
END;

5.3 Add (Option 2)

The program takes the customer number from the input view ENP3CNOI. It resets the broker and payment defaults (CA_PAYMENT = 0, CA_BROKERID = 0, CA_BROKERSREF = blank). It copies the dates and house fields into the COMMAREA, then links to LGAPOL01. On failure it issues a rollback and goes to NO_ADD. On success it echoes the new customer and policy numbers, clears the option field and shows “New House Policy Inserted”.

5.4 Delete (Option 3)

The request is 01DHOU with the customer and policy numbers. A failure issues SYNCPOINT ROLLBACK and goes to NO_DELETE. On success the dates, property fields and option are blanked and “House Policy Deleted” is shown.

5.5 Update (Option 4)

Update is the only operation that holds the task across two terminal interactions. This is a two-phase flow.

sequenceDiagram participant U as Operator participant P as LGTESTP3 participant I as LGIPOL01 participant UP as LGUPOL01 U->>P: Option 4, customer, policy P->>I: LINK 01IHOU I-->>P: Current house data, RC 0 P-->>U: SEND MAP pre-filled U->>P: Edited fields (second RECEIVE MAP) P->>UP: LINK 01UHOU UP-->>P: RC 0 P-->>U: "House Policy Updated" P->>P: RETURN TRANSID SSP3

If the initial inquiry fails, the program goes to NO_DATA and never reaches the update. If the update fails, it goes to NO_UPD with “Error Updating House Policy”. No explicit SYNCPOINT ROLLBACK is issued for update, unlike add and delete.

6.2 Inquiry Request Selection

The request code depends on which keys are supplied. A non-blank postcode always overrides the key-based choice.

graph TD S([Option 1]) --> A{Customer and policy supplied} A -- Yes --> R1[01ICOM] A -- No --> B{Policy only} B -- Yes --> R2[02ICOM] B -- No --> C{Customer only} C -- Yes --> R3[03ICOM] C -- No --> R4[Request ID unchanged] R1 --> P{Postcode entered} R2 --> P R3 --> P R4 --> P P -- Yes --> R5[05ICOM

If neither key nor postcode is supplied, no request ID is set. The previous value is kept, which is blank after start-up or after an error. The program still links to LGIPOL01, and the back-end decides the outcome through its return code.

6.3 Add (Option 2)

The program sets CA_REQUEST_ID to 01ACOM. It copies the customer number and all policy fields from the screen into the COMMAREA. These are the dates, address, postcode, coordinates, customer name, property type, the four peril and premium pairs, status and reject reason. It then links to LGAPOL01.

PLI 
WHEN ('2') DO;
   CA_REQUEST_ID = '01ACOM';
   /* copy screen fields to CA_ISSUE_DATE ... CA_B_RejectReason */
   EXEC CICS LINK PROGRAM('LGAPOL01')
        COMMAREA(COMM_AREA) LENGTH(32500);
   IF CA_RETURN_CODE > 0 THEN DO;
      EXEC CICS SYNCPOINT ROLLBACK;
      GO TO NO_ADD;
   END;
   ENP4CNOI = CA_CUSTOMER_NUM;
   ENP4PNOI = CA_POLICY_NUM;
   ENP4OPTI = ' ';
   ERP4FLDO = 'New Commercial Policy Inserted';
   EXEC CICS SEND MAP('SSMAPP4') FROM(SSMAPP4O) MAPSET('SSMAP');
   GO TO ENDIT_STARTIT;
END;

6.4 Delete (Option 3)

The request is 01DCOM. A failure issues SYNCPOINT ROLLBACK and goes to NO_DELETE, whatever the return code. On success the expiry date, address, postcode, coordinates, customer, property type, perils, premiums, status, reject reason and option fields are blanked. The issue date field is not cleared. The program then shows “Commercial Policy Deleted”.

7. Error Handling and Rollback

7.1 Error Routing

Every failed back-end call goes to an operation-specific label. That label sets a message and falls into the common ERROR_OUT routine.

Label Used by Message
NO_ADD P3, P4 Return code 70: “Customer does not exist”. Otherwise “Error Adding House Policy” or “Error Adding Commercial Policy”.
NO_UPD P3 only “Error Updating House Policy”
NO_DELETE P3, P4 “Error Deleting House Policy” or “Error Deleting Commercial Policy”
NO_DATA P3, P4 “No data was returned.”
PLI 
NO_ADD:
   SELECT (CA_RETURN_CODE);
      WHEN (70)  ERP3FLDO = 'Customer does not exist';
      OTHERWISE  ERP3FLDO = 'Error Adding House Policy';
   END;
   GO TO ERROR_OUT;

7.2 Rollback Policy

Operation House (SSP3) Commercial (SSP4)
Inquire failure No rollback No rollback
Add failure SYNCPOINT ROLLBACK SYNCPOINT ROLLBACK
Delete failure SYNCPOINT ROLLBACK SYNCPOINT ROLLBACK
Update failure No rollback Not applicable

An inquiry is read-only, so it needs no rollback. The house update path relies on the back-end program or CICS to handle recovery.

7.3 ERROR_OUT Reset

ERROR_OUT sends the map with the error text. It then clears all working state so that stale data does not carry into the next iteration. The reset covers these items:

  • The input map SSMAPP3I / SSMAPP4I is blanked.
  • COMM_AREA_RAW is blanked.
  • CA_REQUEST_ID is blank.
  • CA_RETURN_CODE and CA_CUSTOMER_NUM are 0.
  • CA_REQUEST_INITIALISER is blank.

It then goes to ENDIT_STARTIT.

7.5 Unhandled Conditions

The programs have no RESP/RESP2 checks and no PL/I ON ERROR units. Only MAPFAIL is explicitly handled. Any other condition, such as a LINK to an uninstalled program, gets default CICS handling, which normally abends the transaction.

10. Constraints and Design Notes

  • Option validation. Only one option is processed per screen interaction. Any other value, including blank, gets the invalid-option message.
  • No field validation in the menus. The programs copy screen data straight to the COMMAREA. The back-end services must validate dates, numbers and required fields.
  • Add and update defaults (house). CA_PAYMENT = 0, CA_BROKERID = 0 and CA_BROKERSREF = blank.
  • Policy number on add. It is not supplied from the screen. The back-end generates it and the menu shows it.
  • COMMAREA size. All LINK commands pass LENGTH(32500), matching COMM_AREA_RAW.
  • Message length. Messages are limited to 40 characters because ERP3FLDO and ERP4FLDO are CHAR(40).
  • Screen widths. Wider COMMAREA values are truncated on display. Examples are the 25-character address and customer fields on the commercial map.
  • Unreachable code. In LGTESTP3, the plain EXEC CICS RETURN after the SELECT is effectively unreachable. Every branch ends in a GO TO.
  • Inquiry with no keys (commercial). The request ID keeps its earlier value and the back-end is still called.

11.6 Invalid Option

Entering 9 as the option in either menu produces this result:

  • The message “Please enter a valid option” is placed in the message field.
  • The option length field is set to -1, so the cursor is positioned on the option field.
  • No back-end program is called.
  • The map is resent with CURSOR and the transaction returns under its own transaction ID.

Related Pages

Motor and Endowment Policy Menus The 3270 menu programs for motor policies (LGTESTP1, map SSMAPP1) and endowment policies (LGTESTP2). They cover inquire, add, delete and update, plus pseudo-conversational handling and PF3 exit. Policy Inquiry The policy and claim inquiry flow. LGIPOL01 is the business-logic entry point and LGIPDB01 retrieves data from Db2 for each policy type, claims, and multi-record lookups. LGIPVS01 does the generic key browse on the VSAM policy file. Policy Add The new-policy flow. LGAPOL01 orchestrates, optionally calling the ODM business-rules program LGAPBR01. LGAPDB01 inserts into Db2 and LGAPVS01 persists the policy record to the VSAM KSDS. Policy Delete The policy deletion chain. LGDPOL01 dispatches by policy type and LGDPDB01 deletes from the Db2 POLICY table, with child rows removed by foreign-key cascade. LGDPVS01 removes the matching record from the VSAM policy file.
