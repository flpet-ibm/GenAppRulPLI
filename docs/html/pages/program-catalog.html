Program Catalog and Naming Conventions

This technical document details the Enterprise PL/I program inventory and architectural naming conventions for the General Insurance (GenApp) application. It explains the multi-tier taxonomy dividing presentation front-ends, business-logic orchestrators, relational data access layers (Db2), VSAM key-sequenced data set handlers, standalone batch processors, and centralized system error logging utilities.

1. Overview

The GenApp insurance processing system is structured into clearly delineated tiers:

  • Presentation / Menu Drivers: Handle 3270 Basic Mapping Support (BMS) screens, capture attention identifier (AID) keys, and orchestrate user interactions.
  • Business Logic Orchestrators: Validate incoming communication areas (COMMAREA), normalize transaction request codes, enforce business rules, and route work down to persistence subprograms.
  • Persistence Layers: Execute embedded SQL against Db2 for z/OS relational tables or native CICS file control operations against VSAM Key-Sequenced Data Sets (KSDS).
  • Batch Processing: Standalone batch jobs reading sequential customer inputs and producing formatted reports.
  • Cross-Cutting Utilities: Centralized diagnostic, audit, and transient data/temporary storage queue logging.

2. System Architecture

The application implements a decoupled layered architecture where user interfaces and orchestrators communicate using standardized 32,500-byte communication areas (LGCMAREA), insulating UI workflows from database changes.

3. Program Naming Taxonomy

GenApp PL/I program identifiers conform to a standardized 8-character nomenclature indicating functional domain, action type, target entity, persistence mechanism, and revision level:

$\text{Prefix (2)} + \text{Action (1)} + \text{Entity (1)} + \text{Layer / Target (2)} + \text{Sequence (2)}$

CODE 
+---+---+---+---+---+---+---+---+
| L | G | A | C | U | S | 0 | 1 |
+---+---+---+---+---+---+---+---+
  |   |   |   |   |   |   |   |
  +---+   |   |   +---+   +---+
Application Action Target  Persistence/
 Identifier (Add) (Customer)  Layer

3.1 Functional Action Codes

The third character designates the CRUD or lifecycle operation:

  • I (Inquiry): Read-only access to customer profiles or policy structures.
  • A (Add): Create operations for new customers, policies, or security entries.
  • U (Update): Modification of existing customer demographics or policy data.
  • D (Delete): Removal of policy records and cascaded dependent entities.
  • T (Test): Interactive 3270 BMS presentation front-end menu drivers (e.g., LGTESTP1).
  • B (Batch): Non-CICS batch processing routines (e.g., LGBATCH).
  • S (System): Cross-cutting system utilities (e.g., LGSTSQ).

3.2 Target Entity Types

The fourth character indicates the business entity domain:

  • C (Customer): Operations manipulating customer demographic profiles and security credentials.
  • P (Policy): Operations targeting insurance policies across multiple lines of business (Endowment, House, Motor, Commercial, Claim).

3.3 Functional Prefix Combinations

Combining Action and Entity yields standard four-character functional prefixes:

Prefix Domain Description Example Programs
IC Customer Inquiry LGICUS01, LGICDB01, LGICVS01
AC Customer Add / Onboarding LGACUS01, LGACVS01, LGACDB02
UC Customer Update LGUCUS01, LGUCDB01
DC Customer Delete LGDCUS01, LGDCDB01
IP Policy Inquiry LGIPOL01, LGIPDB01
AP Policy Add LGAPOL01, LGAPDB01, LGAPBR01
UP Policy Update LGUPOL01, LGUPDB01
DP Policy Delete LGDPOL01, LGDPDB01

3.4 Suffix and Architectural Layer Designations

Characters 5 through 8 identify the architectural tier and execution model:

  • -US01 / -OL01: Top-level business logic orchestrators and dispatchers. Orchestrators validate EIBCALEN, map request IDs, and manage transaction flow without containing embedded SQL.
  • -DB01 / -DB02: Relational database persistence modules executing static embedded SQL against IBM Db2 for z/OS tables.
  • -VS01: VSAM Key-Sequenced Data Set (KSDS) handlers executing native CICS file control commands (READ FILE, WRITE FILE).
  • -BR01: Business Rules integration modules (e.g., Operational Decision Manager / ODM rule engines).

4.1.2 Code Implementation Example: Customer Query Delegation (LGICUS01)

PLI 
/* Read control queue to check for alternate message queue routing */
 EXEC CICS READQ TS QUEUE(MQ_CONTROL)
           INTO(MQ_READ_RECORD)
           ITEM(1)
           RESP(WS_RESP);

 IF (WS_RESP = DFHRESP(NORMAL)) THEN
   DO UNTIL (WS_RESP > 0);
     IF (SUBSTR(MQ_READ_RECORD,1,6) = 'MQHIT=') THEN
       MQ_HIT = 1;
     EXEC CICS READQ TS QUEUE(MQ_CONTROL)
               INTO(MQ_READ_RECORD)
               NEXT
               RESP(WS_RESP);
   END;

 /* Route to Db2 query layer if no MQ hit detected */
 IF (MQ_HIT = 0) THEN
   EXEC CICS LINK PROGRAM(LGICDB01)
             COMMAREA(COMM_AREA)
             LENGTH(32500);
 ELSE
   EXEC CICS LINK PROGRAM('AAAAAAAA')
             COMMAREA(COMM_AREA)
             LENGTH(32500);

4.2.2 Code Implementation Example: Policy Update Length Validation (LGUPOL01)

PLI 
SELECT (CA_REQUEST_ID);
   WHEN ('01UEND')
     DO;
       WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN;
       WS_REQUIRED_CA_LEN = WS_REQUIRED_CA_LEN + WS_FULL_ENDOW_LEN;
       IF (EIBCALEN < WS_REQUIRED_CA_LEN) THEN
         DO;
           CA_RETURN_CODE = '98';
           EXEC CICS RETURN;
         END;
     END;
   WHEN ('01UHOU')
     DO;
       WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN;
       WS_REQUIRED_CA_LEN = WS_REQUIRED_CA_LEN + WS_FULL_HOUSE_LEN;
       IF (EIBCALEN < WS_REQUIRED_CA_LEN) THEN
         DO;
           CA_RETURN_CODE = '98';
           EXEC CICS RETURN;
         END;
     END;
   WHEN ('01UMOT')
     DO;
       WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN;
       WS_REQUIRED_CA_LEN = WS_REQUIRED_CA_LEN + WS_FULL_MOTOR_LEN;
       IF (EIBCALEN < WS_REQUIRED_CA_LEN) THEN
         DO;
           CA_RETURN_CODE = '98';
           EXEC CICS RETURN;
         END;
     END;
   OTHERWISE
     CA_RETURN_CODE = '99';
 END;

 CALL UPDATE_POLICY_DB2_INFO;

4.4.2 Code Implementation Example: TSQ Override and Logging (LGSTSQ)

PLI 
STSQ = 'GENAERRS';
 IF (SUBSTR(WRITE_MSG_MSG,1,2) = 'Q=') THEN
   DO;
     /* Override TSQ destination name: GENAnnnn */
     SUBSTR(STSQ,5,4) = SUBSTR(WRITE_MSG_MSG,3,4);
     TEMPO            = SUBSTR(WRITE_MSG_MSG,8,83);
     WRITE_MSG_MSG    = TEMPO;
     WS_RECV_LEN      = WS_RECV_LEN - 7;
   END;

 WS_RECV_LEN = WS_RECV_LEN + 5; /* Include SYSID + 1-byte delimiter */

 /* Write to standard CICS message Transient Data Queue */
 EXEC CICS WRITEQ TD QUEUE(STDQ_NAME)
           FROM(WRITE_MSG)
           LENGTH(WS_RECV_LEN)
           RESP(WS_RESP);

 /* Write to GenApp Temporary Storage Queue */
 EXEC CICS WRITEQ TS QUEUE(STSQ)
           FROM(WRITE_MSG)
           LENGTH(WS_RECV_LEN)
           NOSUSPEND
           RESP(WS_RESP);

5. Standardized Communication & Return Codes

5.1 Communication Area Structural Standard

All GenApp CICS business transactions share the 32,500-byte COMM_AREA structure defined in copybook LGCMAREA (plinc/LGCMAREA.inc):

PLI 
DCL 1 COMM_AREA BASED(COMM_AREA_PTR),
       3 CA_REQUEST_ID           CHAR(6),
       3 CA_RETURN_CODE          PIC '99',
       3 CA_CUSTOMER_NUM         PIC '9999999999',
       3 CA_REQUEST_SPECIFIC     UNION,
         5 CA_CUSTOMER_REQUEST   CHAR(32482),
         5 CA_CUSTSECR_REQUEST   CHAR(32482),
         5 CA_POLICY_REQUEST     CHAR(32482);

5.2 Application Return Codes

Return Code Meaning Generating Layers / Programs Description / Recovery Action
'00' Normal Completion / Success All Orchestrators & Db2 Engines Operation succeeded. Target data populated in COMM_AREA.
'01' Record Not Found / Deadlock LGICDB01, LGBATCH Row does not exist (SQLCODE = 100) or deadlock/timeout encountered (SQLCODE = -913).
'70' Foreign Key Violation LGACUS01, LGAPDB01 Insert failed due to missing parent record (SQLCODE = -530, e.g., adding policy for non-existent customer).
'90' General Database Error All Db2 Engines (*DB01, *DB02) Unhandled SQLCODE. Diagnostic details logged to TDQ via LGSTSQ.
'98' COMMAREA Length Error All Orchestrators (*US01, *OL01) EIBCALEN is less than minimum required structure threshold. Transaction halts early.
'99' Unsupported Request ID LGUCUS01, LGUPOL01, LGDPOL01 CA_REQUEST_ID contains an unmapped or invalid operation code.
LGCA Missing COMMAREA Abend All Orchestrators (*US01, *OL01) EIBCALEN = 0. Transaction terminated via EXEC CICS ABEND ABCODE('LGCA') NODUMP.
