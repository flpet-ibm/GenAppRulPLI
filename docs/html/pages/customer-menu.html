Customer Menu (LGTESTC1, SSC1)

1. Overview

LGTESTC1 is a CICS PL/I program that runs as transaction SSC1. It is the 3270 customer menu of the GenApp application. A user can do three things from the BMS map SSMAPC1 (mapset SSMAP):

Option Function Business service linked
1 Inquire a customer LGICUS01
2 Add a customer LGACUS01
4 Update a customer LGICUS01 (read first), then LGUCUS01

The menu has no SQL or file I/O of its own. It does the following:

  • Delegates: it passes work to the customer business services through a shared 32,500-byte COMMAREA (LGCMAREA).
  • Displays results: it shows the returned customer data, or a confirmation or error message, on the 3270 screen.
  • Rejects invalid options: it warns the user and puts the cursor back on the option field.
  • Resets after failures: after any service failure it clears the screen and the COMMAREA.
  • Maintains GENACNTL: after a successful add, it records the range of issued customer numbers (lowest and highest) in the temporary storage queue GENACNTL. Access to the queue is serialised with ENQ/DEQ.
  • Is pseudo-conversational: it keeps its context between interactions and ends with a “Transaction ended” message when the user exits.

The program is declared Options(Main,Reentrant). It is compiled with SYSTEM(CICS) and the CICS and macro preprocessors, and deployed as a CICSLOAD module.

2. System Architecture

2.1 Component View

The menu sits between the 3270 terminal and the customer business services. The services reach Db2 and the other downstream resources. The menu itself touches only the BMS map, the COMMAREA and the GENACNTL queue.

2.2 Architectural Elements

3.3 Inputs Returned by the Services (LGCMAREA)

  • CA_RETURN_CODE: 00 means success. Any value greater than 0 means failure.
  • CA_CUSTOMER_NUM: the new customer number, returned by LGACUS01.
  • CA_FIRST_NAME, CA_LAST_NAME, CA_DOB, CA_HOUSE_NAME, CA_HOUSE_NUM, CA_POSTCODE, CA_PHONE_HOME, CA_PHONE_MOBILE, CA_EMAIL_ADDRESS: customer details returned by LGICUS01.

3.4 Queue Input

READ_MSG (READ_MSG_MSG / READ_CUST_HIGH) is an 80-byte area that receives records read from the GENACNTL queue. It is used to find the HIGH CUSTOMER record.

4. Outputs

4.1 Screen Outputs

  • The output map is SSMAPC1O. It returns the customer fields (ENT1FNAO, ENT1LNAO and so on) and the customer number.
  • ENT1CNOO is initialised to '0000000000' on first entry.
  • ENT1OPTI is cleared after a successful add or update.
  • ERRFLDO (maximum 40 characters) carries these messages:
Message Situation
New Customer Inserted Successful add
Customer details updated Successful update
Please enter a valid option Option not 1, 2 or 4
No data was returned. Inquiry failure (options 1 and 4)
Error Adding Customer Add failure
Error Updating Customer Update failure

4.2 Terminal Messages

MSGEND sends the text 'Transaction ended' when the user presses PF3 or a MAPFAIL occurs.

5. Processing Logic

5.1 Initialisation and First-Invocation Detection

When EIBCALEN is zero, no COMMAREA was passed, so this is the first call. The program does the following:

  1. Points COMM_AREA_PTR at the local BASE_COMM_AREA.
  2. Blanks SSMAPC1I and SSMAPC1O.
  3. Resets CA_REQUEST_ID, CA_RETURN_CODE, CA_CUSTOMER_NUM and the request initialiser.
  4. Sets ENT1CNOO to '0000000000'.
  5. Sends SSMAPC1 with ERASE.

5.2 Receive-and-Dispatch Loop

At label A_GAIN the program registers the attention-key and condition handlers, then receives the map:

PLI 
EXEC CICS HANDLE AID CLEAR(CLEARIT) PF3(ENDIT);
EXEC CICS HANDLE CONDITION MAPFAIL(ENDIT);
EXEC CICS RECEIVE MAP('SSMAPC1') MAPSET('SSMAP') ...;

The map is received with ASIS and TERMINAL, so the text is not folded to uppercase. The program then evaluates ENT1OPTO in a SELECT statement.

flowchart TD S[RECEIVE MAP] --> SEL{ENT1OPTO} SEL -->|'1'| I1[Set 01ICUS, customer number from ENT1CNOO] I1 --> I2[LINK LGICUS01] I2 --> I3{CA_RETURN_CODE greater than 0?} I3 -->|Yes| ND[NO_DATA] I3 -->|No| I4[Copy fields to map, SEND MAP] I4 --> R[ENDIT_STARTIT] SEL -->|'2'| A1[Set 01ACUS, customer number 0, load fields] A1 --> A2[TRANSLATE nulls, UPPERCASE postcode] A2 --> A3[LINK LGACUS01] A3 --> A4{CA_RETURN_CODE greater than 0?} A4 -->|Yes| A5[SYNCPOINT ROLLBACK] A5 --> NA[NO_ADD] A4 -->|No| A6[WRITE_GENACNTL] A6 --> A7[Show number, clear option, New Customer Inserted] A7 --> R SEL -->|'4'| U1[Inquire via LGICUS01, SEND MAP] U1 --> U2[Second RECEIVE MAP] U2 --> U3[Set 01UCUS, load fields, cleanse] U3 --> U4[LINK LGUCUS01] U4 --> U5{CA_RETURN_CODE greater than 0?} U5 -->|Yes| NU[NO_UPD] U5 -->|No| U6[Customer details updated] U6 --> R SEL -->|OTHER| O1[Please enter a valid option, cursor] O1 --> R

5.3 Option 1: Inquire Customer

The program sets the request ID and customer number, links to LGICUS01, and checks the return code. On success it copies the COMMAREA fields to the map:

  • CA_FIRST_NAME → ENT1FNAI
  • CA_LAST_NAME → ENT1LNAI
  • CA_DOB → ENT1DOBI
  • CA_HOUSE_NAME → ENT1HNMI
  • CA_HOUSE_NUM → ENT1HNOI
  • CA_POSTCODE → ENT1HPCI
  • CA_PHONE_HOME → ENT1HP1I
  • CA_PHONE_MOBILE → ENT1HP2I
  • CA_EMAIL_ADDRESS → ENT1HMOI

The map is sent without ERASE.

sequenceDiagram actor User participant Menu as LGTESTC1 (SSC1) participant Svc as LGICUS01 User->>Menu: Option 1 + customer number Menu->>Menu: CA_REQUEST_ID = 01ICUS, CA_CUSTOMER_NUM = ENT1CNOO Menu->>Svc: LINK COMMAREA(COMM_AREA) LENGTH(32500) Svc-->>Menu: Customer details + CA_RETURN_CODE alt CA_RETURN_CODE = 0 Menu-->>User: SEND MAP with customer data else CA_RETURN_CODE greater than 0 Menu-->>User: "No data was returned." end Menu->>Menu: RETURN TRANSID(SSC1) COMMAREA

5.4 Option 2: Add Customer

Before the link, the program zeroes the customer number, loads the screen fields into the COMMAREA, and cleanses the data:

PLI 
CA_REQUEST_ID   = '01ACUS';
CA_CUSTOMER_NUM = 0;
/* ... screen fields moved into CA_ fields ... */
COMM_AREA_RAW = TRANSLATE(COMM_AREA_RAW,' ','00'X);
CA_POSTCODE   = UPPERCASE(CA_POSTCODE);

The null-to-space translation stops unmodified screen fields from passing nulls to the services. The program then links to LGACUS01:

  • Failure: the program issues EXEC CICS SYNCPOINT ROLLBACK and goes to NO_ADD.
  • Success: the program calls WRITE_GENACNTL, sets ENT1CNOI to the new customer number, clears ENT1OPTI, and sets ERRFLDO to 'New Customer Inserted'.
sequenceDiagram actor User participant Menu as LGTESTC1 (SSC1) participant Add as LGACUS01 participant TSQ as TSQ GENACNTL User->>Menu: Option 2 + customer details Menu->>Menu: Load COMMAREA, TRANSLATE nulls, UPPERCASE postcode Menu->>Add: LINK (01ACUS) Add-->>Menu: CA_CUSTOMER_NUM + CA_RETURN_CODE alt Success Menu->>TSQ: ENQ, update or create high/low records, DEQ Menu-->>User: New Customer Inserted else Failure Menu->>Menu: SYNCPOINT ROLLBACK Menu-->>User: Error Adding Customer end

5.5 Option 4: Update Customer

Update is a two-step interaction within one task:

  1. The menu inquires with '01ICUS' and LGICUS01. A return code above 0 goes to NO_DATA.
  2. It sends the map with the current data so the user can edit it.
  3. It issues a second RECEIVE MAP to collect the edits.
  4. It sets CA_REQUEST_ID = '01UCUS', reloads the COMMAREA, applies the same translate and uppercase steps, and links to LGUCUS01.
  5. On a return code above 0 it goes to NO_UPD. Otherwise it refreshes ENT1CNOI, clears ENT1OPTI, and shows 'Customer details updated'.
sequenceDiagram actor User participant Menu as LGTESTC1 (SSC1) participant Inq as LGICUS01 participant Upd as LGUCUS01 User->>Menu: Option 4 + customer number Menu->>Inq: LINK (01ICUS) Inq-->>Menu: Current details Menu-->>User: SEND MAP (current data) User->>Menu: Edited fields (second RECEIVE MAP) Menu->>Menu: 01UCUS, load fields, TRANSLATE, UPPERCASE Menu->>Upd: LINK (01UCUS) Upd-->>Menu: CA_RETURN_CODE Menu-->>User: Customer details updated / Error Updating Customer

5.6 Invalid Option

Any other value, including 3, blank or a non-digit, takes the OTHERWISE branch. The program sets ERRFLDO = 'Please enter a valid option' and ENT1OPTL = -1, sends the map with CURSOR, and returns to SSC1. No service is called.

5.7 Error Paths and Reset

NO_DATA, NO_ADD and NO_UPD each set their message in ERRFLDO and fall to ERROR_OUT. ERROR_OUT does the following:

  1. Sends the map with the error message.
  2. Blanks the input and output maps.
  3. Blanks COMM_AREA_RAW.
  4. Resets CA_REQUEST_ID, CA_RETURN_CODE, CA_CUSTOMER_NUM and the request initialiser.
  5. Goes to ENDIT_STARTIT.

The next interaction therefore starts from a clean COMMAREA.

5.8 Session Control

Label Behaviour
ENDIT_STARTIT EXEC CICS RETURN TRANSID('SSC1') COMMAREA(COMM_AREA) keeps the pseudo-conversation going.
ENDIT Sends 'Transaction ended' with SEND TEXT ... ERASE FREEKB, then does RETURN with no TRANSID.
CLEARIT Blanks SSMAPC1I, sends the map with MAPONLY, and returns with TRANSID('SSC1') and the COMMAREA.

5.9 WRITE_GENACNTL: Control Queue Maintenance

This internal procedure runs only after a successful add. It does the following:

  1. Serialise: it takes EXEC CICS ENQ RESOURCE(STSQ_NAME) and initialises WS_FLAG_TSQH = 'Y' and WS_ITEM_COUNT = 1.
  2. Probe: it reads item 1 of the queue.
  3. Scan: if the read is DFHRESP(NORMAL), it loops with READQ TS ... NEXT while WS_RESP = 0, incrementing WS_ITEM_COUNT.
  4. Update in place: if the item’s first 13 characters are 'HIGH CUSTOMER', it sets WRITE_MSG_HIGH = CA_CUSTOMER_NUM, clears the flag, rewrites that item with WRITEQ TS ... REWRITE ITEM(WS_ITEM_COUNT) (length 24), and sets WS_RESP = 99 to leave the loop.
  5. Initialise if missing: if the flag is still 'Y', it sets both low and high to the new customer number. It then writes the header (20 bytes), low (23 bytes) and high (24 bytes) records with NOSUSPEND.
  6. Release: it issues EXEC CICS DEQ RESOURCE(STSQ_NAME).
flowchart TD A[ENQ GENACNTL] --> B[Flag = Y, item count = 1] B --> C[READQ item 1] C --> D{RESP NORMAL?} D -->|Yes| E[Loop READQ NEXT while WS_RESP = 0] E --> F{First 13 chars = HIGH CUSTOMER?} F -->|Yes| G[Set HIGH = new number, REWRITE item, WS_RESP = 99] F -->|No| E D -->|No| H{Flag still Y?} G --> H E -->|End of queue| H H -->|Yes| I[WRITEQ header, LOW and HIGH = new number] H -->|No| J[DEQ GENACNTL] I --> J

The queue is created on the first successful add. Both bounds then equal the first customer number.

6. Dependencies

6.1 Called Programs

Program Role Request ID
LGICUS01 Customer inquiry. Also the read step of option 4. 01ICUS
LGACUS01 Customer add. Returns the new CA_CUSTOMER_NUM. 01ACUS
LGUCUS01 Customer update 01UCUS
ADDIPGM1 Counter initialisation. Its LINK is commented out, so it is not a runtime dependency. n/a

All calls use COMM_AREA with a length of 32500. A typical call looks like this:

PLI 
EXEC CICS LINK PROGRAM('LGICUS01')
              COMMAREA(COMM_AREA)
              LENGTH(32500);

6.2 Include Files

  • plinc/SSMAP.inc: the symbolic map for SSMAPC1 and SSMAPP1 to SSMAPP5.
  • plinc/LGCMAREA.inc: the 32,500-byte COMMAREA layout.
  • A change to either include requires an impact build or a full build. The compile parameters resolve %INCLUDE against the plinc/*.inc search path.

6.3 Downstream Resources

The services reach the following resources on the menu’s behalf:

  • LGACUS01 writes CUSTOMER and POLICY.
  • LGICUS01 reads CUSTOMER.
  • LGUCUS01 updates CUSTOMER.
  • The customer number counter (GENACUSTNUM, pool GENA) is used on the add path by the services further down the chain.

6.4 Built-in Functions and Runtime

  • TRANSLATE replaces X'00' with blanks.
  • UPPERCASE converts the postcode.
  • STG, ADDR and SUBSTR provide lengths, pointers and queue-record matching.
  • No environment variables are used.
  • The program hard-codes these literals: mapset SSMAP, map SSMAPC1, transaction SSC1, queue GENACNTL, the program names above, and the COMMAREA length 32500.

7. Constraints

7.1 Option Validation and Input Handling

  • Only options 1, 2 and 4 are accepted.
  • The program does not check that the customer number is present, numeric or in range. The called services do those checks.
  • On add, CA_CUSTOMER_NUM is forced to 0 and the service assigns the number.
  • Fields are copied by assignment into fixed lengths, so longer or shorter values are truncated or padded without a report.
Field Length
First name 10
Last name 20
Date of birth 10
House name 20
House number 4
Postcode 8
Phone (each) 20
Email 100
Customer number 10 digits

7.2 Return Codes and Sequencing

  • CA_RETURN_CODE > 0 means failure. The program does not distinguish individual failure codes.
  • Only the add path issues SYNCPOINT ROLLBACK, and it does so before the error message is shown.
  • WRITE_GENACNTL runs after a successful add and before the confirmation map is sent.
  • In the update path, the inquiry uses ENT1CNOO, but the update takes the customer number from ENT1CNOI after the second receive.
  • Pressing Enter with no data raises MAPFAIL, which ends the transaction.

7.3 Queue Consistency

  • High-water mark: the high value is overwritten by the latest add without comparison, so the program assumes numbers only increase.
  • Low value: it is never changed after the queue is created.
  • Responses: RESP values on queue writes are captured but not tested, so a failed queue update does not stop the add or change the user’s reply.

7.4 Capacity Limits

Item Limit
COMMAREA 32,500 bytes
Customer number 10 digits
READ_MSG buffer 80 bytes
WS_ITEM_COUNT FIXED BIN(15), up to 32,767 items
ERRFLDO 40 characters

The program is reentrant. The queue name and exit message are STATIC constants, and no other static state is changed.

8. Error Handling

Area Mechanism
Invalid option OTHERWISE branch with message and cursor repositioning.
CLEAR / PF3 / MAPFAIL HANDLE AID and HANDLE CONDITION route to CLEARIT or ENDIT.
Service failure CA_RETURN_CODE > 0 leads to NO_DATA, NO_ADD or NO_UPD, then ERROR_OUT.
Add failure SYNCPOINT ROLLBACK undoes partial work. The control queue is not advanced.
State reset ERROR_OUT clears the maps, the COMMAREA and the key fields.
Data normalisation Nulls are translated to blanks and the postcode is uppercased before add and update links.
Queue self-healing If the HIGH CUSTOMER record is missing, the header, low and high records are recreated.
Serialisation ENQ/DEQ on GENACNTL. DEQ is always issued at the end of the procedure.

Gaps:

  • There is no general ON-unit.
  • LINK has no RESP option, so conditions such as PGMIDERR fall to the default CICS action (abend).
  • SEND MAP and ENQ/DEQ errors are not trapped either.
  • The second RECEIVE MAP in the update path has no separate failure branch.

9. Examples

9.1 Inquire Customer (Option 1)

Input: ENT1OPTO = '1', ENT1CNOO = '0000000001'.

Flow:

  1. The program sets CA_REQUEST_ID = '01ICUS' and links to LGICUS01.
  2. With CA_RETURN_CODE = 0, the map is populated.
  3. The program returns with TRANSID('SSC1').

Output:

Field Value

ENT1HNMI 'THE COTTAGE '

ENT1HP1I '02079460000 '
ENT1HP2I '07700900000 '
ENT1HMOI 'john.doe@example.com' (padded)

9.2 Add New Customer (Option 2)

Input: ENT1OPTO = '2', first name 'ALICE', last name 'SMITH', DOB '1990-10-25', house name 'HILLSIDE HOUSE', house number '45', postcode 'e1 6an ', home phone '02079460111', mobile '07700900111', email 'alice.smith@example.com'.

Flow:

  1. The program sets CA_REQUEST_ID = '01ACUS' and CA_CUSTOMER_NUM = 0.
  2. The postcode becomes 'E1 6AN '.
  3. The program links to LGACUS01.
  4. WRITE_GENACNTL records the new number.

Output:

Field Value
ENT1CNOI Generated number, for example '0000000042'
ENT1OPTI ' ' (cleared)
ERRFLDO 'New Customer Inserted'
GENACNTL HIGH CUSTOMER=0000000042

9.3 Invalid Option Selection

Input: ENT1OPTO = '9'.

Flow: The value matches none of '1', '2' or '4', so the OTHERWISE branch runs and sends the map with CURSOR.

Output:

  • ERRFLDO = 'Please enter a valid option'.
  • The cursor is placed on the option field (ENT1OPTL = -1).
  • The program returns with TRANSID('SSC1').
PLI 
OTHERWISE DO;
   ERRFLDO  = 'Please enter a valid option';
   ENT1OPTL = -1;
   EXEC CICS SEND MAP('SSMAPC1') MAPSET('SSMAP') CURSOR;
   GO TO ENDIT_STARTIT;
END;
