Policy Inquiry

1. Overview

The Policy Inquiry flow of the insurance application retrieves policy and claim details for a caller. The caller is a front-end menu or another program. Three PL/I CICS programs cooperate in this flow:

Program Role Data source
LGIPOL01 Business-logic entry point. It validates that a COMMAREA exists, sets up the return code, captures the identifiers used for error reporting, and delegates to LGIPDB01. None. It is a pure orchestrator.
LGIPDB01 Db2 retrieval engine. It dispatches on the request ID and reads endowment, house, motor and commercial policies and claims. It also handles the multi-record lookups. Db2 tables POLICY, ENDOWMENT, HOUSE, MOTOR, COMMERCIAL and CLAIM
LGIPVS01 Generic key (GTEQ) browse of the VSAM policy file. It returns the first policy matching a policy type and customer number key. VSAM KSDS KSDSPOLY

The shared communication area (COMM_AREA, 32,500 bytes) is the only data contract between callers and these programs. Its fields are:

  • CA_REQUEST_ID
  • CA_RETURN_CODE
  • CA_CUSTOMER_NUM
  • CA_POLICY_NUM
  • CA_POLICY_COMMON
  • CA_POLICY_SPECIFIC, a union of endowment, house, motor, commercial and claim layouts

Errors are logged through the common logging program LGSTSQ.

3. End-to-End Request Flow

3.1 Sequence of Operations (Successful Db2 Inquiry)

sequenceDiagram participant C as Caller participant O as LGIPOL01 participant D as LGIPDB01 participant DB as Db2 C->>O: LINK with COMM_AREA (request ID, customer, policy) O->>O: Capture EIBTRNID, EIBTRMID, EIBTASKN O->>O: EIBCALEN > 0, set CA_RETURN_CODE = 00 O->>O: Save customer and policy numbers for error messages O->>D: LINK PROGRAM(LGIPDB01) COMMAREA(COMM_AREA) LENGTH(32000) D->>D: GET CONTAINER ICOM-Data (not found, use COMMAREA) D->>D: Uppercase request ID, convert keys to integers D->>DB: SELECT POLICY join type table DB-->>D: SQLCODE 0 and row D->>D: Check EIBCALEN >= required length D->>D: Convert and move data, write FINAL marker D-->>O: COMM_AREA with CA_RETURN_CODE O-->>C: EXEC CICS RETURN with populated COMM_AREA

LGIPOL01 does not examine CA_RETURN_CODE after the LINK. The caller must interpret it.

3.2 Sequence of Operations (Missing COMMAREA)

sequenceDiagram participant C as Caller participant O as LGIPOL01 participant L as LGSTSQ C->>O: LINK (no COMMAREA, EIBCALEN = 0) O->>O: EM_MSG_TEXT = NO COMMAREA RECEIVED O->>O: ASKTIME / FORMATTIME O->>L: LINK with ERROR_MSG L-->>O: Message written to queue O->>O: EXEC CICS ABEND ABCODE(LGCA) NODUMP

4. LGIPOL01: Business-Logic Entry Point

4.1 Responsibilities

LGIPOL01 contains no SQL. It does the following:

  1. Copies the transaction ID, terminal ID and task number into the working-storage header. The eyecatcher is LGIPOL01------WS.
  2. Checks for the presence of a COMMAREA. This is its only validation.
  3. Sets CA_RETURN_CODE to '00'.
  4. Copies CA_CUSTOMER_NUM and CA_POLICY_NUM into the error message fields EM_CUSNUM and EM_POLNUM.
  5. Links to LGIPDB01.
  6. Returns to the caller.

4.2 Processing Flow

graph TD A([Start LGIPOL01]) --> B[Capture EIB identifiers] B --> C{EIBCALEN = 0?} C -- Yes --> D[Write error message
NO COMMAREA RECEIVED] D --> E[ABEND LGCA NODUMP] C -- No --> F[Set CA_RETURN_CODE = 00] F --> G[Copy customer and policy numbers
to error message] G --> H[LINK LGIPDB01
LENGTH 32000] H --> I[EXEC CICS RETURN]

4.3 Code Example: Delegation to LGIPDB01

CODE 
EXEC CICS LINK Program(LGIPDB01)
          Commarea(COMM_AREA)
          Length(32000);

4.4 Error Logging Routine

WRITE_ERROR_MESSAGE stamps the message with the date and time from ASKTIME and FORMATTIME. It then links to LGSTSQ to write the message. If EIBCALEN > 0, it links a second time with up to 90 bytes of the COMMAREA. LGIPOL01 calls it only when EIBCALEN = 0, so the COMMAREA dump never runs there. The routine is defensive code for reuse.

4.5 Limitations

  • There is no RESP handling on the LINK to LGIPDB01. Failures go to CICS default handling.
  • WS_REQUIRED_CA_LEN is declared but never used to validate the COMMAREA length.
  • CA_RETURN_CODE is not checked after the LINK.

5. LGIPDB01: Db2 Retrieval

5.1 Input Selection

LGIPDB01 first tries EXEC CICS GET CONTAINER('ICOM-Data') on channel ICOM.

Condition Behaviour
Container found Container storage becomes the commarea. The request ID and customer number are taken from it. The return code is not reset and the policy number is not converted.
Container not found and EIBCALEN = 0 Writes NO COMMAREA RECEIVED and abends with LGCA.
Container not found and EIBCALEN > 0 Sets the return code to 00, converts the customer and policy numbers to integers, saves them for error messages, and upper-cases the request ID.

CODE 
SELECT (WS_REQUEST_ID)

   OTHERWISE CA_RETURN_CODE = '99'

5.3 Single-Row Inquiries

Endowment, house, motor, commercial (01ICOM and 02ICOM) and single claim all follow the same pattern.

graph TD A[Singleton SELECT
POLICY join type table] --> B{SQLCODE} B -- 0 --> C{EIBCALEN >= 33 + full length?} B -- 100 --> D[CA_RETURN_CODE = 01] B -- Other --> E[CA_RETURN_CODE = 90
WRITE_ERROR_MESSAGE] C -- No --> F[CA_RETURN_CODE = 98
EXEC CICS RETURN] C -- Yes --> G[Convert integers to numeric pictures
Move common fields
SUBSTR type-specific block to CA_POLICY_RAW
Write FINAL marker]

Key points:

  • Required length. The header/trailer length (33) is added to the full length of the policy type. Endowment adds the non-null padding length.
  • Nullable columns. Broker ID, broker reference, payment and the endowment padding data use indicator variables. Broker ID and payment are moved only when the indicator is not -1.
  • Staging. Db2 output goes into working storage first, so that the commarea length can be checked before any data is moved.
  • Motor. CA_M_PREMIUM and CA_M_ACCIDENTS are assigned explicitly, because WS_MOTOR_LEN (65) is shorter than the full motor structure.
  • End marker. The literal FINAL is written after the data. For endowment it goes after the padding data. For the other types it goes in the filler field.
Policy type Type data length Full length (incl. header 33)
Endowment 52 124 (plus padding)
House 58 130
Motor 65 137
Commercial 1102 1174
Claim 546 618

5.4 Multi-Record Inquiries

graph TD A[OPEN cursor] --> B{SQLCODE = 0?} B -- No --> C[CA_RETURN_CODE = 89
WRITE_ERROR_MESSAGE] B -- Yes --> D[FETCH loop
DO UNTIL SQLCODE > 0] C --> D D --> E[CLOSE cursor] E --> F{SQLCODE = 0?} F -- No --> G[CA_RETURN_CODE = 88
WRITE_ERROR_MESSAGE] F -- Yes --> H[Done]
Request Cursor Key Output behaviour
03ICOM Cust_Cursor Customer number Records are appended in container storage. The loop stops once the count exceeds 20. ICOM-Data (count × 1202 bytes) and ICOM-Count (2 bytes) are put on channel ICOM.
05ICOM Zip_Cursor CA_B_POSTCODE Each fetched row overwrites the same commarea area, so only the last row remains. There is no count, no container output and no cap.
02ICLM CusClaim_Cursor Customer number Each row overwrites the previous one. FINAL is written after each row.

For 03ICOM, the record cap works as follows:

CODE 
IF ICOM_Record_Count > 20 THEN SQLCODE = 17;   /* force loop exit */

The check happens after the 21st row has been fetched and stored, so up to 21 rows can be stored.

5.5 Return Codes

Code Meaning
00 Success
01 No row found (SQLCODE 100). Invalid customer, policy or claim number.
88 Cursor CLOSE failed
89 Cursor OPEN failed
90 Unexpected SQLCODE on a SELECT. An error is logged.
98 COMMAREA too small. LGIPDB01 returns immediately.
99 Request ID not recognised

5.6 Known Behaviours and Discrepancies

  • The 01ICOM, 02ICOM and 01ICLM paths read common-policy host variables such as DB2_BROKERID and DB2_PAYMENT, but their SELECTs do not populate them.
  • For 01ICOM and 02ICOM, the SELECT maps RequestDate, StartDate and RenewalDate into last-changed, issue and expiry. This differs from the order of the declared names.
  • The claim routines copy DB2_CLAIM_TEXT using WS_COMM_LEN (1102) instead of WS_CLAIM_LEN (546).
  • An OPEN failure does not stop the fetch loop.
  • A negative SQLCODE on FETCH does not end the loop.
  • A cursor that returns no rows does not set return code 01.

6. LGIPVS01: VSAM Generic Browse

6.1 Purpose

LGIPVS01 uses a generic GTEQ read against KSDSPOLY. The partial key is 11 bytes: a 1-byte policy type plus a 10-digit customer number. It returns the first policy record at or after that key, provided its policy type matches the requested type. The record layout is policy type (1), customer number (10), policy number (10) and 43 bytes of filler, 64 bytes in total.

6.2 Invocation Modes

Mode Detection Input Output
Program call (WS_FLAG = 'C') STARTCODE starts with D, or INVOKINGPROG is not blank COMMA_DATA_TEXT || COMMA_DATA_KEY, length fixed at 10 COMMA_DATA_TEXT and COMMA_DATA_KEY in the COMMAREA
Terminal (WS_FLAG = 'R') Any other case EXEC CICS RECEIVE, with the length reduced by 6 EXEC CICS SEND TEXT (80 bytes)

6.4 Code Example: Generic Read

CODE 
EXEC CICS READ FILE('KSDSPOLY')
     INTO(CA_AREA)
     LENGTH(F64)
     RIDFLD(PART_KEY)
     KEYLENGTH(F11)
     GENERIC
     GTEQ
     RESP(WS_RESP);

6.5 Result Rules

  • A lookup succeeds only if WS_RESP = DFHRESP(NORMAL) and CA_POLICY_TYPE = PART_KEY_TYPE.
  • A GTEQ read can return a record with a higher key. Only the policy type is compared, so the returned customer number may differ from the one requested.
  • Failure gives Policy Bad= with placeholder value 13 in the customer and policy number fields. The program cannot tell NOTFND, ENDFILE or IOERR apart.
  • Only the first matching record is returned. There is no browse loop.

6.6 Example: Terminal Request

Input:

CODE 
LGPV E0000000001

Output:

CODE 
Policy Key=E0000000001

When the lookup fails, the output is Policy Bad=, with 0000000013 in both the customer and policy number positions.

7.2 Summary by Program

Program Abends Reported via Notes
LGIPOL01 LGCA when EIBCALEN = 0 CA_RETURN_CODE set by LGIPDB01 Does not check the return code. No RESP handling on LINK.
LGIPDB01 LGCA when no container and EIBCALEN = 0 CA_RETURN_CODE (01, 88, 89, 90, 98, 99) Logging calls have no response checks.
LGIPVS01 None Policy Bad= message with placeholder 13 Input is not validated. Non-numeric input could raise a PL/I conversion condition.

7.3 Error Message Content

The ERROR_MSG structure sent to LGSTSQ holds:

  • the date (EM_DATE) and time (EM_TIME)
  • the program tag
  • the customer number (EM_CUSNUM) and policy number (EM_POLNUM)
  • the SQL request description (for example SELECT MOTOR)
  • the SQLCODE (EM_SQLRC)

A second record carries COMMAREA= followed by up to 90 bytes of the commarea.

9. Examples

9.1 Motor Policy Inquiry (Success)

Input COMMAREA:

Field Value
CA_REQUEST_ID 01IMOT
CA_CUSTOMER_NUM 0000000001
CA_POLICY_NUM 0000000001
  1. LGIPOL01 confirms that EIBCALEN > 0, sets the return code to 00 and links to LGIPDB01.
  2. LGIPDB01 runs GET_MOTOR_DB2_INFO, which issues a singleton SELECT on POLICY joined with MOTOR.
  3. The required length is 33 + 137 = 170, and EIBCALEN is large enough.
  4. The common fields, motor block, premium and accidents are moved. FINAL is written in CA_M_FILLER.
  5. LGIPOL01 returns the populated COMMAREA to the caller. CA_RETURN_CODE is 00.

9.2 Commercial Policies by Customer (03ICOM)

For a customer with 3 commercial policies:

  • Three records of 1202 bytes each are placed in the ICOM-Data container, 3606 bytes in total.
  • ICOM-Count holds 3.
  • The return code stays 00.

9.3 Failure Cases

Scenario Result
No COMMAREA passed to LGIPOL01 The error is logged through LGSTSQ and the task abends with LGCA.
01IHOU for a policy that does not exist CA_RETURN_CODE = 01
01IEND with EIBCALEN = 100 CA_RETURN_CODE = 98 (157 or more bytes needed)
01XXXX request ID CA_RETURN_CODE = 99
LGIPVS01 finds no record or a different type Policy Bad= with placeholder 13
