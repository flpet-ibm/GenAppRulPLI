Environment Setup and Reset (LGSETUP)

The LGSETUP utility is a core CICS PL/I maintenance program designed to reset and initialize the General Insurance (GenApp) demonstration environment to a clean, known operational state. It purges transient runtime temporary storage queues, recreates application boundary control records, reseeds the centralized customer numbering generator, and resets all transaction-level success and failure statistical counters across customer and policy domains.

1. Overview

1.1 Purpose and Functional Scope

In an active CICS testing and demonstration environment, application runs generate accumulated error logs, transaction timestamps, status items, and updated customer records. LGSETUP acts as an automated reset facility that restores the GenApp application infrastructure without requiring a CICS region restart or cold start.

The program performs the following core tasks:

  • Temporary Storage Queue Purging: Deletes legacy queues holding errors (GENAERRS), startup markers (GENASTRT), execution status (GENASTAT), and configuration boundaries (GENACNTL).
  • Control Queue Reconstruction: Rebuilds the GENACNTL queue with structured low and high customer limits (defaulting to a range of 1 to 11, or an operator-supplied upper bound).
  • Customer Named Counter Reseeding: Reinitializes the CICS named counter GENACUSTNUM within the GENA pool to ensure subsequent customer creation programs (such as LGACDB01 or LGACVS01) allocate sequential identifiers starting above the baseline dataset.
  • Transaction Statistics Reset: Systematically loops through 36 named statistical counters in the GENA pool, zeroing out transaction outcome counters across all business operations (Inquire, Add, Delete, Update) and domain entities (Customer, Motor, Endowment, House, Commercial).
  • Visual Completion Feedback: Formats and outputs the active high customer boundary directly to the terminal user, clearing the screen and releasing keyboard locks.

1.2 Operational Characteristics

LGSETUP is implemented as a single, self-contained PL/I main procedure (Options(Main)) that executes directly under CICS via the LGSE transaction code. It requires no relational database attachments (no DB2/SQL calls) and relies strictly on standard CICS TSQ and Named Counter Server facilities.

2.2 Component Interaction & Descriptions

  • CICS Terminal Interface: Accepts transaction input (LGSE [value]) and delivers terminal output (HIGH CUSTOMER=nnnnnnnnnn) via direct CICS terminal control commands (RECEIVE, SEND TEXT).
  • CICS Temporary Storage Control (TSQ): Provides non-persistent or auxiliary memory queues used across GenApp transactions. LGSETUP resets all standard queues to ensure clean application execution.
  • CICS Named Counter Server (Pool GENA): A shared cross-region/sysplex facility managing atomic integer sequences. LGSETUP configures both the generator for primary keys (GENACUSTNUM) and the performance/monitoring matrix of 36 metrics counters.
  • Downstream Programs (LGICVS01, LGACDB01): Inquire and Add routines depend on the boundaries defined in GENACNTL and the current integer held in GENACUSTNUM to locate existing records and assign unique primary keys without collision.

3.3 Detailed Execution Steps

  1. Terminal Input Capture: LGSETUP issues EXEC CICS RECEIVE INTO(WS_RECV) LENGTH(WS_RECV_LEN) RESP(WS_RESP) to read the input stream.
  2. Boundary Resolution: If the input length exceeds 5 bytes (the 4-character transaction ID plus a separating delimiter), the remaining slice SUBSTR(WS_RECV_DATA, 1, WS_RECV_LEN) is cast into LASTCUSTNUM. If 5 or fewer bytes were entered, LASTCUSTNUM defaults to 11.
  3. Queue Deletion: Four consecutive EXEC CICS DELETEQ TS commands purge GENAERRS, GENASTRT, GENASTAT, and GENACNTL. Missing queues return condition codes trapped in WS_RESP and are safely ignored.
  4. Queue Initialization: Three records are sequentially appended to GENACNTL with NOSUSPEND:
    • Item 1 (Length 20): Eyecatcher **** GENAPP CNTL
    • Item 2 (Length 23): LOW CUSTOMER=0000000001
    • Item 3 (Length 24): HIGH CUSTOMER=nnnnnnnnnn
  5. Customer Counter Seeding: GENACUSTNUM is purged and recreated in pool GENA with VALUE(LASTCUSTNUM).
  6. Statistics Matrix Loop: An indexed loop traverses COUNTER_ARRAY(1..36), issuing DELETE COUNTER followed by DEFINE COUNTER VALUE(0) for each counter.
  7. Screen Display and Exit: The 24-byte record containing HIGH CUSTOMER=nnnnnnnnnn is written to the terminal via EXEC CICS SEND TEXT with ERASE, WAIT, and FREEKB, followed by EXEC CICS RETURN.

4. Input and Output Interfaces

4.1 Terminal Input Parameters

The transaction input buffer layout is defined as follows:

PLI 
DCL 1 WS_RECV,
      3 WS_RECV_TRANID    CHAR(5),
      3 WS_RECV_DATA      CHAR(74);

DCL WS_RECV_LEN          FIXED BIN(15) INIT(80);
  • WS_RECV_TRANID: Holds the initiating transaction code (LGSE ).
  • WS_RECV_DATA: Optional numeric string overriding the maximum customer boundary.
  • WS_RECV_LEN: Halfword integer initialized to 80 bytes; receives the actual input byte count from CICS.

4.2 Temporary Storage Queue Structures (TSQ)

LGSETUP controls four dedicated temporary storage queues:

Queue Name Variable Name Purpose Actions
GENAERRS STSQ_ERRS Accumulated error records from application failures DELETEQ
GENASTRT STSQ_STRT Application start timestamps and run markers DELETEQ
GENASTAT STSQ_STAT Transaction execution logs and statuses DELETEQ
GENACNTL STSQ_NAME Active customer range boundary configuration DELETEQ, then WRITEQ (3 items)

Control Queue Record Structure (WRITE_MSG)

PLI 
DCL 1 WRITE_MSG,
      3 WRITE_MSG_E       CHAR(20) INIT('**** GENAPP CNTL    '),
      3 WRITE_MSG_L       CHAR(13) INIT('LOW CUSTOMER='),
      3 WRITE_MSG_LOW     PIC '(10)9',
      3 FILLER1           CHAR(1)  INIT(' '),
      3 WRITE_MSG_H       CHAR(14) INIT('HIGH CUSTOMER='),
      3 WRITE_MSG_HIGH    PIC '(10)9',
      3 FILLER2           CHAR(60) INIT(' ');
  • Item 1: Written from WRITE_MSG_E with LENGTH(20).
  • Item 2: Written from WRITE_MSG_L with LENGTH(23) (encompasses WRITE_MSG_L + WRITE_MSG_LOW).
  • Item 3: Written from WRITE_MSG_H with LENGTH(24) (encompasses WRITE_MSG_H + WRITE_MSG_HIGH).

4.3 CICS Named Counters (Pool GENA)

Primary Key Generator

  • Counter Name: GENACUSTNUM (GENACOUNT)
  • Pool Name: GENA (GENAPOOL)
  • Configured Initial Value: LASTCUSTNUM (Default 11, or input value)

Performance & Transaction Statistics Matrix

The program manages 36 discrete counters using a static definition table overlaid with a based array:

PLI 
DCL COUNTER_COUNT FIXED BIN(15) INIT(36);
DCL 1 COUNTER_TABLE STATIC,
      3 C01  CHAR(16) INIT('GENA01ICUS00    '),
      3 C02  CHAR(16) INIT('GENA01ICUS99    '),
      3 C03  CHAR(16) INIT('GENA01ACUS00    '),
      3 C04  CHAR(16) INIT('GENA01ACUS99    '),
      3 C05  CHAR(16) INIT('GENA01UCUS00    '),
      3 C06  CHAR(16) INIT('GENA01UCUS99    '),
      3 C07  CHAR(16) INIT('GENA01IMOT00    '),
      3 C08  CHAR(16) INIT('GENA01IMOT99    '),
      ...
      3 C35  CHAR(16) INIT('GENA01DCOM00    '),
      3 C36  CHAR(16) INIT('GENA01DCOM99    ');

DCL 1 COUNTER_ARRAY BASED(ADDR(COUNTER_TABLE)),
      3 COUNTER_NAME(36) CHAR(16);

Counter Naming Convention

Counters adhere to a strict 16-character naming syntax: $\text{GENA01} + \text{Operation} + \text{Entity} + \text{Status}$

  • Prefix: GENA01 (Application release identifier)
  • Operation: I (Inquiry), A (Add), D (Delete), U (Update)
  • Entity: CUS (Customer), MOT (Motor), END (Endowment), HOU (House), COM (Commercial)
  • Status Suffix: 00 (Success count), 99 (Failure count)

Note: Commercial policies support Inquiry, Add, and Delete operations; no Commercial Update counter is defined.

4.4 Terminal Output and Display Format

Upon completion, LGSETUP executes:

PLI 
EXEC CICS SEND TEXT FROM(WRITE_MSG_H)
          TERMINAL WAIT ERASE LENGTH(24) FREEKB;

This clears the terminal screen and displays:

TEXT 
HIGH CUSTOMER=0000000011

5. Technical Constraints and Implementation Rules

5.1 Input and Buffer Constraints

  • Receive Buffer Dimensions: WS_RECV is declared as 79 characters (WS_RECV_TRANID CHAR(5) + WS_RECV_DATA CHAR(74)), while WS_RECV_LEN is initialized to 80.
  • Numeric Casting: Data extracted via SUBSTR(WS_RECV_DATA, 1, WS_RECV_LEN) is implicitly converted to FIXED BIN(31). Any non-numeric characters will trigger a PL/I runtime conversion condition.
  • Lower Boundary Invariant: FRSTCUSTNUM is fixed at 1 (INIT(1)) and cannot be altered via input parameters.

5.2 Control Message Layout and Fixed Offsets

  • Physical Write Lengths: Write operations against GENACNTL use hardcoded lengths (20, 23, 24) that rely on contiguous variable storage within the WRITE_MSG structure.
  • Asynchronous Safeguards: All WRITEQ TS calls specify NOSUSPEND, ensuring the transaction fails immediately with a condition code rather than blocking tasks if TS storage is constrained.

5.3 Named Counter Pool and Matrix Sizing

  • Pool Mapping: All counter commands must target POOL('GENA').
  • Overlay Alignment: The overlay COUNTER_ARRAY relies on ADDR(COUNTER_TABLE). COUNTER_COUNT (36) must strictly match the table dimension to avoid storage boundary overruns.

5.4 Error Handling and Silenced Conditions

  • Uniform RESP Parameter: Every CICS service command includes RESP(WS_RESP). This suppresses default CICS abends on conditions such as QIDERR (queue not found) or INVREQ (counter not found during deletion).
  • Silent Tolerance: WS_RESP is deliberately uninspected. This ensures that a cold-start reset (where resources do not yet exist) executes seamlessly without manual intervention.

6. Execution Examples

6.1 Example 1: Default Environment Setup (No Input Override)

Execution Command

TEXT 
LGSE

Processing Trace

  1. WS_RECV_LEN returns 4 (or 5 with trailing space).
  2. WS_RECV_LEN > 5 evaluates to false; LASTCUSTNUM remains 11.
  3. Existing queues GENAERRS, GENASTRT, GENASTAT, GENACNTL are deleted.
  4. GENACNTL is populated with:
    • Item 1: **** GENAPP CNTL
    • Item 2: LOW CUSTOMER=0000000001
    • Item 3: HIGH CUSTOMER=0000000011
  5. GENACUSTNUM counter is defined with seed 11.
  6. All 36 statistics counters are defined with 0.

Terminal Output

TEXT 
HIGH CUSTOMER=0000000011

6.2 Example 2: Explicit High Customer Number Override

Execution Command

TEXT 
LGSE 0000000500

Processing Trace

  1. WS_RECV_LEN returns 15.
  2. Length check passes: data length is $15 - 5 = 10$.
  3. SUBSTR(WS_RECV_DATA, 1, 10) extracts '0000000500', assigning 500 to LASTCUSTNUM.
  4. Queues are cleared and rebuilt; GENACNTL Item 3 receives HIGH CUSTOMER=0000000500.
  5. GENACUSTNUM counter is seeded with 500.
  6. All 36 statistics counters are reset to 0.

Terminal Output

TEXT 
HIGH CUSTOMER=0000000500

6.3 Example 3: Abbreviated Numeric Override

Execution Command

TEXT 
LGSE 250

Processing Trace

  1. WS_RECV_LEN returns 8.
  2. Length adjustment: $8 - 5 = 3$.
  3. Data string '250' is converted to 250 and assigned to LASTCUSTNUM.
  4. WRITE_MSG_HIGH formats the numeric picture as 0000000250.
  5. GENACUSTNUM is seeded with 250.

Terminal Output

TEXT 
HIGH CUSTOMER=0000000250

6.4 Example 4: Initial Region Cold Start (Missing Resources)

Scenario

Executed in a freshly initialized CICS region where none of the TS queues or named counters exist.

Processing Trace

  1. DELETEQ TS commands encounter QIDERR (queue does not exist); response captured in WS_RESP and bypassed.
  2. DELETE COUNTER commands return condition codes indicating non-existent counter entities; bypassed.
  3. WRITEQ TS successfully creates GENACNTL and adds items 1 through 3.
  4. DEFINE COUNTER successfully establishes GENACUSTNUM and all 36 statistics counters in pool GENA.

Terminal Output

TEXT 
HIGH CUSTOMER=0000000011
