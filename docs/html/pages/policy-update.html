Policy Update

The Policy Update subsystem in the GenApp core insurance application manages the modification and synchronization of active insurance policies across relational and keyed file storage layers. It coordinates request validation, optimistic concurrency verification, Db2 table updates across base and subtype tables, and VSAM KSDS record rewriting within a CICS transaction boundary.

1. Overview

The policy update flow is executed across a three-tiered modular architecture:

  1. Request Validation and Dispatch (LGUPOL01): Acts as the business layer orchestrator. It receives the CICS Communication Area (COMM_AREA), verifies that the payload meets policy-type length requirements, and links to the Db2 persistence backend.
  2. Relational Persistence and Concurrency Management (LGUPDB01): Implements optimistic concurrency control (OCC) using timestamp comparison combined with pessimistic Db2 cursor locking (SELECT FOR UPDATE). It persists modifications to subtype tables (ENDOWMENT, HOUSE, or MOTOR), executes a positioned update against the core POLICY table, generates a new timestamp, and synchronizes the VSAM layer.
  3. VSAM Data Store Synchronization (LGUPVS01): Receives the updated policy context, constructs a 21-character composite key, locks the existing VSAM Key Sequenced Data Set (KSDSPOLY) record via READ UPDATE, and applies the changes via REWRITE.

Diagnostic logging across all components is routed through the centralized logging module LGSTSQ to capture error state and payload snapshots.

3. End-to-End Processing Logic and Workflow

3.1 Orchestration and Validation (LGUPOL01)

LGUPOL01 serves as the entry point and boundary controller:

  • Commarea Presence: Inspects EIBCALEN. If EIBCALEN = 0, it writes a failure message via LGSTSQ and terminates execution with abend code LGCA (NODUMP).
  • Request Type Identification & Length Validation: Evaluates CA_REQUEST_ID and verifies that the payload length satisfies the minimum threshold:
    • '01UEND' (Endowment): Minimum required length = Header (28 bytes) + Full Endowment (124 bytes) = 152 bytes.
    • '01UHOU' (House): Minimum required length = Header (28 bytes) + Full House (130 bytes) = 158 bytes.
    • '01UMOT' (Motor): Minimum required length = Header (28 bytes) + Full Motor (137 bytes) = 165 bytes.
    • Other Request Types: Sets CA_RETURN_CODE = '99' (unsupported) and proceeds without short-circuiting.
  • Length Rejection: If EIBCALEN < WS_REQUIRED_CA_LEN, CA_RETURN_CODE is set to '98' and control returns immediately to the caller without invoking backend persistence routines.
  • Backend Invocation: Validated requests trigger UPDATE_POLICY_DB2_INFO, issuing EXEC CICS LINK PROGRAM('LGUPDB01') passing the full 32,500-byte COMM_AREA_RAW.

3.2 Relational Persistence and Concurrency (LGUPDB01)

LGUPDB01 handles relational persistence and data integrity:

  • Lock Acquisition: Opens POLICY_CURSOR configured WITH HOLD ... FOR UPDATE OF ISSUEDATE, EXPIRYDATE, LASTCHANGED, BROKERID, BROKERSREFERENCE filtered by CUSTOMERNUMBER and POLICYNUMBER.
  • Fetch & Null Handling: Executes FETCH_DB2_POLICY_ROW using null indicators (IND_BROKERID, IND_BROKERSREF, IND_PAYMENT).
  • Optimistic Concurrency Check: Compares the incoming CA_LASTCHANGED with the fetched DB2_LASTCHANGED. If they differ, the record has been concurrently modified; processing stops, CA_RETURN_CODE is set to '02', and the cursor is closed.
  • Subtype Table Updates: Upon timestamp validation, routes to the appropriate sub-procedure based on CA_REQUEST_ID:
    • UPDATE_ENDOWMENT: Updates WITHPROFITS, EQUITIES, MANAGEDFUND, FUNDNAME, TERM, SUMASSURED, LIFEASSURED.
    • UPDATE_HOUSE: Updates PROPERTYTYPE, BEDROOMS, VALUE, HOUSENAME, HOUSENUMBER, POSTCODE.
    • UPDATE_MOTOR: Updates MAKE, MODEL, VALUE, REGNUMBER, COLOUR, CC, YEAROFMANUFACTURE, PREMIUM, ACCIDENTS.
  • Core Table Positioned Update: Executes UPDATE POLICY ... WHERE CURRENT OF POLICY_CURSOR applying CA_ISSUE_DATE, CA_EXPIRY_DATE, DB2_BROKERID_INT, CA_BROKERSREF, and setting LASTCHANGED = CURRENT TIMESTAMP.
  • Timestamp Refresh & Unit of Recovery: Re-queries LASTCHANGED into CA_LASTCHANGED to provide the calling client with the new concurrency token. If this query or the update fails, an explicit EXEC CICS SYNCPOINT ROLLBACK is executed, undoing both subtype and base updates.
  • Downstream Sync: Issues EXEC CICS LINK PROGRAM('LGUPVS01') passing the updated COMM_AREA with a length of 225 bytes.

3.3 VSAM Keyed Record Persistence (LGUPVS01)

LGUPVS01 updates the corresponding record in KSDSPOLY:

  • Key Construction: Extracts the 4th character of CA_REQUEST_ID (C, E, H, or M) as WF_Request_ID and combines it with CA_CUSTOMER_NUM (10 digits) and CA_POLICY_NUM (10 digits) to form the 21-character WF_Policy_Key.
  • Record Mapping: Populates WF_Policy_Info with type-specific attributes based on WF_Request_ID (or blanks WF_Policy_Text if unrecognised).
  • Record Locking: Executes EXEC CICS READ FILE('KSDSPOLY') UPDATE using WF_Policy_Key. If non-normal, sets CA_RETURN_CODE = '81', logs diagnostics via LGSTSQ, and abends LGV3.
  • Record Persistence: Executes EXEC CICS REWRITE FILE('KSDSPOLY') FROM(WF_POLICY_INFO) LENGTH(64). If non-normal, sets CA_RETURN_CODE = '82', logs diagnostics via LGSTSQ, and abends LGV4.

4. Concurrency Control and Data Integrity

The subsystem combines pessimistic relational locking with optimistic application-level version checking to maintain data integrity across distributed and concurrent update transactions.

4.1 Optimistic Concurrency Control (OCC)

  • Token Verification: When reading a policy record, the client receives CA_LASTCHANGED. During the update phase, LGUPDB01 fetches the latest row and compares CA_LASTCHANGED with DB2_LASTCHANGED.
  • Collision Mitigation: If another transaction has modified the row in the interim, the timestamps mismatch, preventing “lost updates”. The update is rejected with CA_RETURN_CODE = '02' without modifying any table.

4.2 Pessimistic Row Locking and Positioned Updates

  • Cursor Locking: POLICY_CURSOR is declared WITH HOLD ... FOR UPDATE OF ISSUEDATE, EXPIRYDATE, LASTCHANGED, BROKERID, BROKERSREFERENCE.
  • Positioned Update: Executing UPDATE POLICY ... WHERE CURRENT OF POLICY_CURSOR ensures that the write lock held during the fetch phase directly protects the positioned row update.

4.3 Transactional Rollback

  • Syncpoint Rollback: If an error occurs while writing the core POLICY row or retrieving the refreshed timestamp (SELECT LASTCHANGED), LGUPDB01 issues EXEC CICS SYNCPOINT ROLLBACK.
  • Integrity Boundary: This rollback cleans up changes applied to the subtype tables (ENDOWMENT, HOUSE, or MOTOR) earlier in the same logical unit of work (LUW).

6. Error Handling and Diagnostics

6.1 Return Code Matrix

The following table lists all status codes generated across the policy update chain:

Return Code Issuing Module Description Severity / Action
'00' All Update completed successfully across Db2 and VSAM. Success
'01' LGUPDB01 Policy record not found in Db2 (SQLCODE 100). Warning / Business Error
'02' LGUPDB01 Optimistic lock failure (CA_LASTCHANGED mismatch). Concurrency Conflict
'81' LGUPVS01 VSAM READ UPDATE failure against KSDSPOLY. Fatal / Abend LGV3
'82' LGUPVS01 VSAM REWRITE failure against KSDSPOLY. Fatal / Abend LGV4
'90' LGUPDB01 General Db2 SQL error or cursor failure. Critical / Rolled Back
'98' LGUPOL01 Supplied COMMAREA length is less than minimum required. Validation Failure
'99' LGUPOL01 Unsupported CA_REQUEST_ID action code. Warning / Forwarded

6.2 Abend Codes and Queue Logging (LGSTSQ)

When critical unrecoverable conditions occur, diagnostic error records are formatted and dispatched to LGSTSQ before triggering a CICS abnormal termination:

CODE 
+-------------------------------------------------------------------------+
| ERROR_MSG Layout                                                        |
|  EM_DATE (10) | EM_TIME (8) | Program Name (8)                          |

  • Abend LGV3 (NODUMP): Triggered by LGUPVS01 when EXEC CICS READ UPDATE on KSDSPOLY returns a non-normal response code.
  • Abend LGV4 (NODUMP): Triggered by LGUPVS01 when EXEC CICS REWRITE on KSDSPOLY returns a non-normal response code.

7. Code Examples and Implementation Snippets

7.1 LGUPOL01 Request Routing and Length Validation

LGUPOL01 verifies incoming commarea lengths before invoking backend modules:

PLI 
/* Evaluate Request Type and Required COMMAREA Length */
SELECT ( CA_REQUEST_ID );
  WHEN ( '01UEND' ) DO;
    WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN + WS_FULL_ENDOW_LEN;
    IF ( EIBCALEN < WS_REQUIRED_CA_LEN ) THEN DO;
      CA_RETURN_CODE = '98';
      EXEC CICS RETURN;
    END;
  END;
  WHEN ( '01UHOU' ) DO;
    WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN + WS_FULL_HOUSE_LEN;
    IF ( EIBCALEN < WS_REQUIRED_CA_LEN ) THEN DO;
      CA_RETURN_CODE = '98';
      EXEC CICS RETURN;
    END;
  END;
  WHEN ( '01UMOT' ) DO;
    WS_REQUIRED_CA_LEN = WS_CA_HEADER_LEN + WS_FULL_MOTOR_LEN;
    IF ( EIBCALEN < WS_REQUIRED_CA_LEN ) THEN DO;
      CA_RETURN_CODE = '98';
      EXEC CICS RETURN;
    END;
  END;
  OTHERWISE DO;
    CA_RETURN_CODE = '99';
  END;
END;

/* Delegate to Db2 Persistence Layer */
CALL UPDATE_POLICY_DB2_INFO;

UPDATE_POLICY_DB2_INFO: PROCEDURE;
  EXEC CICS LINK PROGRAM('LGUPDB01')
            COMMAREA(COMM_AREA_RAW)
            LENGTH(32500);
END UPDATE_POLICY_DB2_INFO;

7.2 LGUPDB01 Optimistic Lock and Positioned Cursor Update

LGUPDB01 executes optimistic timestamp validation and positioned updates:

PLI 
/* Declare and Open Update Cursor */
EXEC SQL DECLARE POLICY_CURSOR CURSOR WITH HOLD FOR
  SELECT ISSUEDATE, EXPIRYDATE, LASTCHANGED, BROKERID, BROKERSREFERENCE
    FROM POLICY
    WHERE CUSTOMERNUMBER = :DB2_CUSTOMERNUM_INT
      AND POLICYNUMBER   = :DB2_POLICYNUM_INT
    FOR UPDATE OF ISSUEDATE, EXPIRYDATE, LASTCHANGED, BROKERID, BROKERSREFERENCE;

EXEC SQL OPEN POLICY_CURSOR;

/* Fetch and OCC Verification */
CALL FETCH_DB2_POLICY_ROW;
IF ( SQLCODE = 0 ) THEN DO;
  IF ( CA_LASTCHANGED = DB2_LASTCHANGED ) THEN DO;
    /* Route to Subtype Table Update */
    SELECT ( CA_REQUEST_ID );
      WHEN ( '01UEND' ) CALL UPDATE_ENDOW_DB2_INFO;
      WHEN ( '01UHOU' ) CALL UPDATE_HOUSE_DB2_INFO;
      WHEN ( '01UMOT' ) CALL UPDATE_MOTOR_DB2_INFO;
    END;
    
    /* Positioned Update on Base POLICY Table */
    EXEC SQL
      UPDATE POLICY
        SET ISSUEDATE        = :CA_ISSUE_DATE,
            EXPIRYDATE       = :CA_EXPIRY_DATE,
            LASTCHANGED      = CURRENT TIMESTAMP,
            BROKERID         = :DB2_BROKERID_INT,
            BROKERSREFERENCE = :CA_BROKERSREF
        WHERE CURRENT OF POLICY_CURSOR;
        
    /* Retrieve Generated Timestamp */
    EXEC SQL
      SELECT LASTCHANGED
        INTO :CA_LASTCHANGED
        FROM POLICY
        WHERE POLICYNUMBER = :DB2_POLICYNUM_INT;
        
    IF ( SQLCODE <> 0 ) THEN DO;
      EXEC CICS SYNCPOINT ROLLBACK;
      CA_RETURN_CODE = '90';
    END;
  END;
  ELSE DO;
    /* OCC Mismatch Collision */
    CA_RETURN_CODE = '02';
  END;
END;
CALL CLOSE_PCURSOR;

7.3 LGUPVS01 VSAM Record Locking and Rewrite

LGUPVS01 performs key preparation, record locking, and rewriting against KSDSPOLY:

PLI 
/* Construct 21-Byte Composite Key */
WF_REQUEST_ID   = SUBSTR(CA_REQUEST_ID, 4, 1);
WF_CUSTOMER_NUM = CA_CUSTOMER_NUM;
WF_POLICY_NUM   = CA_POLICY_NUM;

/* Populate Type-Specific Working Record */
SELECT ( WF_REQUEST_ID );
  WHEN ( 'M' ) DO;
    WF_M_MAKE      = CA_M_MAKE;
    WF_M_MODEL     = CA_M_MODEL;
    WF_M_VALUE     = CA_M_VALUE;
    WF_M_REGNUMBER = CA_M_REGNUMBER;
  END;
  OTHERWISE DO;
    WF_POLICY_TEXT = ' ';
  END;
END;

/* Lock Record in KSDSPOLY */
EXEC CICS READ
          FILE('KSDSPOLY')
          INTO(WS_FILEIN)
          RIDFLD(WF_POLICY_KEY)
          KEYLENGTH(21)
          UPDATE
          RESP(WS_RESP)
          RESP2(WS_RESP2);

IF WS_RESP ^= DFHRESP(NORMAL) THEN DO;
  CA_RETURN_CODE = '81';
  CALL WRITE_ERROR_MESSAGE;
  EXEC CICS ABEND ABCODE('LGV3') NODUMP;
END;

/* Rewrite Updated Record */
EXEC CICS REWRITE
          FILE('KSDSPOLY')
          FROM(WF_POLICY_INFO)
          LENGTH(WS_COMMAREA_LENF)
          RESP(WS_RESP)
          RESP2(WS_RESP2);

IF WS_RESP ^= DFHRESP(NORMAL) THEN DO;
  CA_RETURN_CODE = '82';
  CALL WRITE_ERROR_MESSAGE;
  EXEC CICS ABEND ABCODE('LGV4') NODUMP;
END;
