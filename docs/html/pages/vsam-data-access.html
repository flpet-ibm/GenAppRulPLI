VSAM KSDS Data Access Programs

The VSAM Key-Sequenced Data Set (KSDS) data access programs form the persistence and retrieval layer of the General Insurance (GenApp) application under CICS. These programs manage record-level operations against the customer master file (KSDSCUST) and the policy master file (KSDSPOLY). They support read, write, update (read-for-update and rewrite), delete, generic partial-key browsing, and pseudo-random customer range inquiries. When data store operations fail, these routines coordinate structured error reporting, logging diagnostic payloads via a central temporary storage logging module (LGSTSQ), assigning return codes, and triggering specific CICS transaction abends.

1. Overview

The GenApp core data model segregates business data into customer master entities and associated multi-type policy entities. Interaction with these entities is partitioned across dedicated CICS PL/I subprograms that handle specific file access operations:

  • Customer Data Set (KSDSCUST) Operations:

    • LGICVS01: Customer inquiry and pseudo-random customer record retrieval using range boundaries maintained in CICS Temporary Storage Queues (GENACNTL) and generic GTEQ reads.
    • LGACVS01: Customer insertion (EXEC CICS WRITE) keyed by a 10-digit customer number.
    • LGUCVS01: Customer modification using exclusive lock acquisition (EXEC CICS READ ... UPDATE) followed by replacement (EXEC CICS REWRITE).

  • Policy Data Set (KSDSPOLY) Operations:

    • LGIPVS01: Generic partial-key policy inquiry (EXEC CICS READ ... GENERIC GTEQ) matching on policy type and customer number.
    • LGAPVS01: Policy record insertion (EXEC CICS WRITE) formatting type-specific polymorphic payloads (Commercial, Endowment, House, Motor) indexed by a 21-character composite key.
    • LGUPVS01: Policy update using exclusive record locking (READ ... UPDATE) and subsequent replacement (REWRITE).
    • LGDPVS01: Direct policy deletion (EXEC CICS DELETE) keyed by the 21-character composite policy identifier.

All write and update routines enforce strict response code verification (DFHRESP(NORMAL)), routing failures through diagnostic routines that capture CICS EIBRESP/EIBRESP2 values, assemble standardized error structures, capture input communication area snapshots, and issue designated failure codes.

2. System Architecture and Component Interaction

The VSAM data access modules operate as back-end services invoked by business orchestrators (e.g., LGACDB01, LGAPOL01, LGUPOL01) via EXEC CICS LINK, or directly via CICS 3270 terminal transactions.

2.2 Component Roles and Call Interfaces

Programs dynamically determine execution context at runtime using EXEC CICS ASSIGN STARTCODE and EXEC CICS ASSIGN INVOKINGPROG. If initiated via program link or Distributed Program Link (DPL), communication occurs across the shared LGCMAREA communication area pointer (COMM_AREA_PTR). If executed directly as a 3270 terminal transaction, data is received via EXEC CICS RECEIVE and returned formatted through EXEC CICS SEND TEXT.

3. VSAM Datasets and Key Structures

3.1 Customer Master Dataset (KSDSCUST)

The KSDSCUST dataset contains customer demographic, address, contact, and security summaries.

  • Record Length: 225 bytes (fixed buffer layout)
  • Primary Key: CA_CUSTOMER_NUM (10 bytes, PIC '9999999999')
  • Key Offset: Position 0 (starting at the front of the record)

Record Layout Overview:

  • 01-10: Customer Number (CA_CUSTOMER_NUM, 10 digits)
  • 11-20: First Name (CA_FIRST_NAME, 10 characters)
  • 21-40: Last Name (CA_LAST_NAME, 20 characters)
  • 41-50: Date of Birth (CA_DOB, 10 characters)
  • 51-70: House Name (CA_HOUSE_NAME, 20 characters)
  • 71-74: House Number (CA_HOUSE_NUM, 4 characters)
  • 75-82: Postcode (CA_POSTCODE, 8 characters)
  • 83-85: Number of Active Policies (CA_NUM_POLICIES, 3 digits)
  • 86-105: Mobile Phone (CA_PHONE_MOBILE, 20 characters)
  • 106-125: Home Phone (CA_PHONE_HOME, 20 characters)
  • 126-225: Email Address (CA_EMAIL_ADDRESS, 100 characters)

3.2 Policy Master Dataset (KSDSPOLY)

The KSDSPOLY dataset contains all active insurance policies across multiple lines of business.

  • Record Length: 64 bytes (fixed layout WF_Policy_Info)
  • Primary Key: WF_POLICY_KEY (21 bytes composite)
    • WF_REQUEST_ID: 1-byte policy type discriminator (C = Commercial, E = Endowment, H = House, M = Motor)
    • WF_CUSTOMER_NUM: 10-byte customer number (PIC '9999999999')
    • WF_POLICY_NUM: 10-byte policy identifier (PIC '9999999999')
  • Payload Data: WF_POLICY_DATA (43-byte polymorphic union mapping specific policy properties)

Polymorphic 43-Byte Data Union Structures:

  • Commercial ('C'):
    • WF_B_POSTCODE (8 chars), WF_B_STATUS (halfword binary), WF_B_CUSTOMER (31 chars)
  • Endowment ('E'):
    • WF_E_WITH_PROFITS (1 char), WF_E_EQUITIES (1 char), WF_E_MANAGED_FUND (1 char), WF_E_FUND_NAME (10 chars), WF_E_LIFE_ASSURED (30 chars)
  • House ('H'):
    • WF_H_PROPERTY_TYPE (15 chars), WF_H_BEDROOMS (3 digits), WF_H_VALUE (8 digits), WF_H_POSTCODE (8 chars), WF_H_HOUSE_NAME (9 chars)
  • Motor ('M'):
    • WF_M_MAKE (15 chars), WF_M_MODEL (15 chars), WF_M_VALUE (6 digits), WF_M_REGNUMBER (7 chars)

4. Customer Data Access Programs

4.1 Inquiry and Key Range Selection (LGICVS01)

LGICVS01 supplies a valid, existing customer number for inquiry and testing tasks. It implements pseudo-random selection bounded by control limits stored in the GENACNTL Temporary Storage Queue (TSQ).

Processing Flow:

  1. Invocation Check: Inspects STARTCODE and INVOKINGPROG. If called via LINK/DPL, it flags mode 'C'. If called via 3270 terminal, it receives input and flags mode 'R'.
  2. Control Queue Serialization: Executes EXEC CICS ENQ RESOURCE('GENACNTL') to serialize access across concurrent tasks.
  3. Queue Reading and Initialization:
    • Reads item 1 of GENACNTL. If the queue is missing, boundaries default to 1000001 (low) and 1000001 (high).
    • Loops sequentially reading items: parses LOW CUSTOMER= into WS_CUST_LOW and HIGH CUSTOMER= into WS_CUST_HIGH.
    • Writes missing records using EXEC CICS WRITEQ TS QUEUE('GENACNTL') NOSUSPEND to populate initial control entries.
  4. Lock Release: Releases serialization via EXEC CICS DEQ RESOURCE('GENACNTL').
  5. Key Generation: Uses the CICS task number (EIBTASKN) as a seed: $\text{WS_RANDOM_NUMBER} = \lfloor \text{RANDOM}(\text{EIBTASKN}) \times (\text{WS_CUST_HIGH} - \text{WS_CUST_LOW}) + \text{WS_CUST_LOW} \rfloor$
  6. VSAM Greater-Than-or-Equal Search: Executes EXEC CICS READ FILE('KSDSCUST') RIDFLD(WRITE_MSG_HIGH) KEYLENGTH(10) GTEQ. If a record is found, it extracts CA_CUSTOMER_NUM. If NOTFND, it keeps the random number.
  7. Output Routing: Returns HIGH CUSTOMER= and the 10-digit customer number in the caller’s COMMAREA (WS_FLAG = 'C') or transmits it to the terminal screen via EXEC CICS SEND TEXT (WS_FLAG = 'R').

4.2 Customer Creation (LGACVS01)

LGACVS01 performs direct customer inserts into KSDSCUST.

  • Invoked via EXEC CICS LINK from orchestrator LGACDB01.
  • Issues EXEC CICS WRITE FILE('KSDSCUST') FROM(CA_CUSTOMER_NUM) LENGTH(EIBCALEN) RIDFLD(CA_CUSTOMER_NUM) KEYLENGTH(10).
  • If WS_RESP ^= DFHRESP(NORMAL):
    • Captures EIBRESP2 into WS_RESP2.
    • Sets CA_RETURN_CODE = '80'.
    • Calls WRITE_ERROR_MESSAGE to log the failure and COMMAREA snapshot to LGSTSQ.
    • Abends the task immediately via EXEC CICS ABEND ABCODE('LGV0') NODUMP.

4.3 Customer Update (LGUCVS01)

LGUCVS01 executes atomic customer record updates.

  • Reads and locks the target record via EXEC CICS READ FILE('KSDSCUST') UPDATE INTO(WS_CUSTOMER_AREA) RIDFLD(CA_CUSTOMER_NUM) KEYLENGTH(10).
    • On failure: Captures RESP2, sets CA_RETURN_CODE = '81', links to LGSTSQ, and abends with ABCODE('LGV1') NODUMP.
  • Rewrites the updated record from COMMAREA data via EXEC CICS REWRITE FILE('KSDSCUST') FROM(CA_CUSTOMER_NUM) LENGTH(WS_COMMAREA_LENF).
    • On failure: Captures RESP2, sets CA_RETURN_CODE = '82', links to LGSTSQ, and abends with ABCODE('LGV2') NODUMP.

5. Policy Data Access Programs

5.1 Generic Policy Inquiry and Browse (LGIPVS01)

LGIPVS01 executes a generic partial-key browse across KSDSPOLY.

  1. Input Key Assembly: Reads 1-byte policy type (PART_KEY_TYPE) and up to 10-digit customer number (PART_KEY_NUM) from COMMAREA (WS_FLAG = 'C') or terminal input (WS_FLAG = 'R').
  2. Generic GTEQ Execution: Issues EXEC CICS READ FILE('KSDSPOLY') INTO(CA_AREA) LENGTH(64) RIDFLD(PART_KEY) KEYLENGTH(11) GENERIC GTEQ.
  3. Type Match Validation:
    • Because GTEQ can locate records with a higher key, the program explicitly compares the retrieved CA_POLICY_TYPE against the requested PART_KEY_TYPE.
    • Match & NORMAL: Formats output with header 'Policy Key=' and composite key CA_POLICY_TYPE || CA_CUSTOMER_NUM.
    • Mismatch or Non-NORMAL: Formats output with header 'Policy Bad=' and placeholder numeric keys 0000000013 for customer and policy fields.
  4. Delivery: Transmits via 3270 SEND TEXT or returns within COMMA_DATA.

5.2 Policy Creation (LGAPVS01)

LGAPVS01 creates new policy records in KSDSPOLY.

  • Key Formation: Extracts WF_REQUEST_ID from character 4 of CA_REQUEST_ID, WF_CUSTOMER_NUM from CA_CUSTOMER_NUM, and WF_POLICY_NUM from CA_POLICY_NUM to construct the 21-byte WF_POLICY_KEY.
  • Polymorphic Mapping: Evaluates WF_REQUEST_ID in a SELECT statement:
    • 'C': Maps CA_B_* fields into commercial structure.
    • 'E': Maps CA_E_* fields into endowment structure.
    • 'H': Maps CA_H_* fields into house structure.
    • 'M': Maps CA_M_* fields into motor structure.
    • OTHERWISE: Blanks out WF_POLICY_TEXT.
  • VSAM Insertion: Issues EXEC CICS WRITE FILE('KSDSPOLY') FROM(WF_POLICY_INFO) LENGTH(64) RIDFLD(WF_POLICY_KEY) KEYLENGTH(21).
  • Failure Handling: If not NORMAL, sets CA_RETURN_CODE = '80', formats error records, links to LGSTSQ, and executes EXEC CICS RETURN (returns control without abending).

5.3 Policy Update (LGUPVS01)

LGUPVS01 performs in-place modifications of existing policy records.

  • Constructs the 21-byte WF_POLICY_KEY and maps the appropriate polymorphic data union.
  • Locks the record via EXEC CICS READ FILE('KSDSPOLY') UPDATE INTO(WS_FILEIN) RIDFLD(WF_POLICY_KEY) KEYLENGTH(21).
    • Failure: Sets CA_RETURN_CODE = '81', logs diagnostics to LGSTSQ, and abends with ABCODE('LGV3') NODUMP.
  • Replaces the record via EXEC CICS REWRITE FILE('KSDSPOLY') FROM(WF_POLICY_INFO) LENGTH(64).
    • Failure: Sets CA_RETURN_CODE = '82', logs diagnostics to LGSTSQ, and abends with ABCODE('LGV4') NODUMP.

5.4 Policy Deletion (LGDPVS01)

LGDPVS01 deletes policy records directly.

  • Assembles WF_POLICY_KEY (21 bytes) using the 4th character of CA_REQUEST_ID, CA_CUSTOMER_NUM, and CA_POLICY_NUM.
  • Issues EXEC CICS DELETE FILE('KSDSPOLY') RIDFLD(WF_POLICY_KEY) KEYLENGTH(21).
  • If WS_RESP ^= DFHRESP(NORMAL):
    • Captures EIBRESP2.
    • Sets CA_RETURN_CODE = '81'.
    • Calls WRITE_ERROR_MESSAGE to log diagnostics to LGSTSQ.
    • Concludes with EXEC CICS RETURN (no abend issued).

6.2 Diagnostic Logging Protocol (LGSTSQ)

When a file operation fails in LGACVS01, LGUCVS01, LGAPVS01, LGUPVS01, or LGDPVS01, the internal procedure WRITE_ERROR_MESSAGE is executed prior to termination:

  1. Timestamp Generation: Retrieves absolute system time using EXEC CICS ASKTIME and formats date (MMDDYYYY) and time (HH:MM:SS) using EXEC CICS FORMATTIME.
  2. Primary Diagnostic Record (ERROR_MSG):
    • Formatted structure containing timestamp, program identifier, customer number (EM_CUSNUM), operation description (e.g., "Write file KSDSCUST" or "Re-write KSDSPOLY"), signed numeric RESP (EM_RESPRC), and signed numeric RESP2 (EM_RESP2RC).
    • Transmitted via EXEC CICS LINK PROGRAM('LGSTSQ') COMMAREA(ERROR_MSG) LENGTH(STG(ERROR_MSG)).
  3. Payload Diagnostic Record (CA_ERROR_MSG):
    • If EIBCALEN > 0, the first 90 bytes of raw COMMAREA data are extracted (LEFT(COMM_AREA_RAW, 90)) with prefix COMMAREA=.
    • Transmitted via a second EXEC CICS LINK PROGRAM('LGSTSQ').

7. Program Code Logic and Implementation Examples

7.1 Generic GTEQ Read Implementation

In LGIPVS01, generic partial key reads allow browsing for the first policy record matching a specified policy type and customer key:

PLI 
/* Build partial search key: 1 byte type + 10 digits customer number */
CA_AREA = '';
PART_KEY_TYPE = SUBSTR(WS_COMMAREA, 1, 1);
PART_KEY_NUM  = SUBSTR(WS_COMMAREA, 2, WS_RECV_LEN);

/* Execute generic GTEQ search */
EXEC CICS READ FILE('KSDSPOLY')
          INTO(CA_AREA)
          LENGTH(F64)
          RIDFLD(PART_KEY)
          KEYLENGTH(F11)
          GENERIC
          GTEQ
          RESP(WS_RESP);

/* Validate both normal response and exact type match */
IF (CA_POLICY_TYPE ^= PART_KEY_TYPE | WS_RESP ^= DFHRESP(NORMAL)) THEN DO;
    WRITE_MSG_TEXT = 'Policy Bad=';
    WRITE_MSG_CUSTNUM = 13;
    WRITE_MSG_POLNUM  = 13;
END;
ELSE DO;
    WRITE_MSG_KEY_CH = CA_POLICY_TYPE || CA_CUSTOMER_NUM;
END;

7.2 Read-for-Update and Rewrite Pattern

In LGUCVS01 and LGUPVS01, atomic updates require acquiring an exclusive lock via READ UPDATE prior to REWRITE:

PLI 
/* Step 1: Read for update to acquire exclusive record lock */
EXEC CICS READ FILE('KSDSCUST')
          UPDATE
          INTO(WS_CUSTOMER_AREA)
          LENGTH(WS_COMMAREA_LEN)
          RIDFLD(CA_CUSTOMER_NUM)
          KEYLENGTH(10)
          RESP(WS_RESP);

IF (WS_RESP ^= DFHRESP(NORMAL)) THEN DO;
    WS_RESP2 = EIBRESP2;
    CA_RETURN_CODE = '81';
    CALL WRITE_ERROR_MESSAGE;
    EXEC CICS ABEND ABCODE('LGV1') NODUMP;
    EXEC CICS RETURN;
END;

/* Step 2: Rewrite record with updated content from COMMAREA */
EXEC CICS REWRITE FILE('KSDSCUST')
          FROM(CA_CUSTOMER_NUM)
          LENGTH(WS_COMMAREA_LENF)
          RESP(WS_RESP);

IF (WS_RESP ^= DFHRESP(NORMAL)) THEN DO;
    WS_RESP2 = EIBRESP2;
    CA_RETURN_CODE = '82';
    CALL WRITE_ERROR_MESSAGE;
    EXEC CICS ABEND ABCODE('LGV2') NODUMP;
    EXEC CICS RETURN;
END;

7.3 Direct Record Deletion Pattern

In LGDPVS01, records are removed from KSDSPOLY using the full 21-character composite key:

PLI 
/* Construct 21-byte composite key */
WF_REQUEST_ID   = SUBSTR(CA_REQUEST_ID, 4, 1);
WF_POLICY_NUM   = CA_POLICY_NUM;
WF_CUSTOMER_NUM = CA_CUSTOMER_NUM;

/* Execute direct delete */
EXEC CICS DELETE FILE('KSDSPOLY')
          RIDFLD(WF_POLICY_KEY)
          KEYLENGTH(21)
          RESP(WS_RESP);

IF (WS_RESP ^= DFHRESP(NORMAL)) THEN DO;
    WS_RESP2 = EIBRESP2;
    CA_RETURN_CODE = '81';
    CALL WRITE_ERROR_MESSAGE;
    EXEC CICS RETURN;
END;

7.4 Diagnostic Message Assembly and Logging

The standardized error reporting implementation across the data access suite captures environmental data and payload dumps:

PLI 
WRITE_ERROR_MESSAGE: PROC;
    /* Retrieve and format system timestamp */
    EXEC CICS ASKTIME ABSTIME(WS_ABSTIME);
    EXEC CICS FORMATTIME ABSTIME(WS_ABSTIME)
              MMDDYYYY(WS_DATE)
              TIME(WS_TIME);

    /* Assemble structured error information */
    EM_DATE    = WS_DATE;
    EM_TIME    = WS_TIME;
    EM_CUSNUM  = CA_CUSTOMER_NUM;
    EM_RESPRC  = WS_RESP;
    EM_RESP2RC = WS_RESP2;

    /* Link to logging utility */
    EXEC CICS LINK PROGRAM('LGSTSQ')
              COMMAREA(ERROR_MSG)
              LENGTH(STG(ERROR_MSG));

    /* Conditionally capture raw COMMAREA payload snapshot */
    IF (EIBCALEN > 0) THEN DO;
        IF (EIBCALEN < 91) THEN
            CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN);
        ELSE
            CA_DATA = LEFT(COMM_AREA_RAW, 90);

        EXEC CICS LINK PROGRAM('LGSTSQ')
                  COMMAREA(CA_ERROR_MSG)
                  LENGTH(STG(ERROR_MSG));
    END;
END WRITE_ERROR_MESSAGE;
