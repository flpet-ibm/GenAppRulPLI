Motor and Endowment Policy Menus

1. Overview

The Motor and Endowment Policy Menus are the CICS 3270 front-end screens of the GenApp insurance application. They let a terminal operator work with two policy types.

Program Transaction BMS Map (Mapset SSMAP) Policy Type
LGTESTP1 SSP1 SSMAPP1 Motor policies
LGTESTP2 SSP2 SSMAPP2 Endowment (life) policies

Both programs are written in PL/I and compiled as Options(Main,Reentrant). They follow the same pattern:

  • The operator enters a one-character menu option on the map: 1 inquire, 2 add, 3 delete, 4 update.
  • The program fills a shared COMMAREA (COMM_AREA, 32,500 bytes) with a request code and the screen data.
  • The program calls a back-end policy program with EXEC CICS LINK.
  • The program shows the result, or an error message, on the same screen.
  • The program ends the task with EXEC CICS RETURN TRANSID(...). This is pseudo-conversational processing, so the menu is ready for the next key press.
  • PF3 ends the session with a “Transaction ended” message. CLEAR redisplays a blank menu.

The menu programs do no database or file I/O and issue no SQL. All persistence is done by the linked back-end programs: LGIPOL01, LGAPOL01, LGUPOL01 and LGDPOL01.

2.2 Shared Resources

Resource Role
Mapset SSMAP (plinc/SSMAP.inc) Symbolic maps SSMAPC1, SSMAPP1 to SSMAPP5, as ...I input and ...O output structures. LGTESTP1 uses only SSMAPP1 and LGTESTP2 uses only SSMAPP2.
LGCMAREA (plinc/LGCMAREA.inc) COMM_AREA layout based on COMM_AREA_PTR. It has a 32,500-byte raw redefinition and holds the common header, the motor fields (CA_M_*) and the endowment fields (CA_E_*).
DFHEIPTR / EIBCALEN The CICS EXEC interface block pointer. EIBCALEN = 0 marks first entry.
BASE_COMM_AREA Local storage that backs the COMMAREA on first entry.

2.3 Request Codes

The request ID is a 6-character code. The first two characters are 01, the next character is the action, and the last three identify the policy type.

Operation Motor (LGTESTP1) Endowment (LGTESTP2) Back-end Program
Inquire 01IMOT 01IEND LGIPOL01
Add 01AMOT 01AEND LGAPOL01
Delete 01DMOT 01DEND LGDPOL01
Update 01UMOT 01UEND LGUPOL01

3. Pseudo-Conversational Processing

3.1 Entry and Re-entry

Both programs use EIBCALEN to tell a first call from a re-entry.

  • First entry (EIBCALEN = 0).
    • COMM_AREA_PTR is set to BASE_COMM_AREA.
    • The output map is cleared.
    • CA_REQUEST_ID is blanked. CA_RETURN_CODE and CA_CUSTOMER_NUM are set to zero. CA_REQUEST_INITIALISER is cleared.
    • The numeric display fields are set to zeros.
    • The empty menu is sent with ERASE.
  • Re-entry. The program skips the initial display and goes straight to A_GAIN.
PLI 
IF EIBCALEN = 0 THEN DO;
   /* point COMMAREA at local base storage, clear map and header fields */
   /* set numeric display fields to zeros */
   EXEC CICS SEND MAP('SSMAPP1') MAPSET('SSMAP') ERASE;
END;

On first entry, LGTESTP1 sets the customer number, policy number, value, CC, accidents and premium fields to zeros. LGTESTP2 sets only the customer number and policy number to '0000000000'.

3.2 Handlers and Receive

At A_GAIN, each pass registers these handlers and then receives the map:

  • HANDLE AID CLEAR goes to CLEARIT.
  • HANDLE AID PF3 goes to ENDIT.
  • HANDLE CONDITION MAPFAIL goes to ENDIT.
  • RECEIVE MAP reads the screen into the ...I structure.
  • SELECT on the option field (ENP1OPTO or ENP2OPTO) dispatches the request.

3.3 Lifecycle Sequence

sequenceDiagram participant User as 3270 User participant CICS participant Menu as LGTESTP1 / LGTESTP2 User->>CICS: Enter transaction SSP1 or SSP2 CICS->>Menu: Start, EIBCALEN = 0 Menu->>User: SEND MAP with ERASE Menu->>CICS: RETURN TRANSID COMMAREA User->>CICS: Fill in option and data, press Enter CICS->>Menu: Restart with COMMAREA Menu->>Menu: HANDLE AID and CONDITION Menu->>Menu: RECEIVE MAP and SELECT option Menu->>User: SEND MAP with result Menu->>CICS: RETURN TRANSID COMMAREA User->>CICS: Press PF3 CICS->>Menu: Restart Menu->>User: SEND TEXT Transaction ended Menu->>CICS: RETURN, no TRANSID

3.4 Exit Routines

Routine Trigger Action
ENDIT_STARTIT After every handled outcome EXEC CICS RETURN TRANSID('SSP1' or 'SSP2') COMMAREA(COMM_AREA)
ENDIT PF3 or MAPFAIL SEND TEXT FROM(MSGEND) ERASE FREEKB, then a plain RETURN that ends the conversation
CLEARIT CLEAR key Clears the map structure, sends the map with MAPONLY, and returns with the transaction ID and COMMAREA
PLI 
ENDIT_STARTIT:
   EXEC CICS RETURN TRANSID('SSP1') COMMAREA(COMM_AREA);

ENDIT:
   EXEC CICS SEND TEXT FROM(MSGEND) ERASE FREEKB;
   EXEC CICS RETURN;

MSGEND holds the text 'Transaction ended'.

4.3 Option Behaviour

4.3.1 Option 1 – Inquire

  • Sets CA_REQUEST_ID to 01IMOT.
  • Takes the customer and policy numbers from ENP1CNOO and ENP1PNOO.
  • Links to LGIPOL01.
  • If CA_RETURN_CODE > 0, goes to NO_DATA.
  • Otherwise copies the issue date, expiry date, make, model, value, registration, colour, CC, manufactured date, premium and accidents to the map and sends it.
PLI 
CA_REQUEST_ID = '01IMOT';
CA_CUSTOMER_NUM = ENP1CNOO;
CA_POLICY_NUM   = ENP1PNOO;
EXEC CICS LINK PROGRAM('LGIPOL01') COMMAREA(COMM_AREA) LENGTH(32500);
IF CA_RETURN_CODE > 0 THEN GO TO NO_DATA;

4.3.2 Option 2 – Add

  • Sets CA_REQUEST_ID to 01AMOT.
  • Takes the customer number from ENP1CNOI.
  • Sets CA_PAYMENT and CA_BROKERID to 0 and CA_BROKERSREF to blank.
  • Copies all motor fields from the screen.
  • Links to LGAPOL01.
  • On a non-zero return code, issues SYNCPOINT ROLLBACK and goes to NO_ADD.
  • On success, echoes the new customer and policy numbers, clears the option field and shows “New Motor Policy Inserted”.

4.3.3 Option 3 – Delete

  • Sets CA_REQUEST_ID to 01DMOT.
  • Passes the customer and policy numbers.
  • Links to LGDPOL01.
  • On a non-zero return code, issues SYNCPOINT ROLLBACK and goes to NO_DELETE.
  • On success, blanks the date and vehicle fields and shows “Motor Policy Deleted”.

4.3.4 Option 4 – Update (two-step)

  1. Inquire with 01IMOT through LGIPOL01. A failure goes to NO_DATA. On success, the current values are displayed.
  2. A second RECEIVE MAP collects the operator’s edits.
  3. Build 01UMOT, reset the payment and broker fields, and link to LGUPOL01.
  4. A non-zero return code goes to NO_UPD. There is no rollback on this path. On success the program shows “Motor Policy Updated”.

4.3.5 Any Other Option

The program sets “Please enter a valid option” and ENP1OPTL = -1 to place the cursor on the option field. It then sends the map with CURSOR and returns to SSP1.

5.3 Option Behaviour

5.3.1 Option 1 – Inquire

  • Sets CA_REQUEST_ID to 01IEND.
  • Takes the customer number from ENP2CNOO and the policy number from ENP2PNOO.
  • Links to LGIPOL01.
  • On success, moves the issue date, expiry date, fund name, term, sum assured, life assured, with-profits, managed-fund and equities values to the screen.

5.3.2 Option 2 – Add

  • Sets CA_REQUEST_ID to 01AEND.
  • Takes the customer number from ENP2CNOI.
  • Resets the payment and broker fields.
  • Copies the dates and endowment fields from the screen.
  • Links to LGAPOL01.
  • On a non-zero return code, issues SYNCPOINT ROLLBACK and goes to NO_ADD.
  • On success, echoes the customer number, new policy number and fund name. It blanks the option field and shows “New Life Policy Inserted”.

5.3.3 Option 3 – Delete

  • Sets CA_REQUEST_ID to 01DEND.
  • Links to LGDPOL01.
  • On a non-zero return code, issues SYNCPOINT ROLLBACK and goes to NO_DELETE.
  • On success, blanks the detail fields (ENP2IDAI, ENP2EDAI, ENP2FNMI, ENP2TERI, ENP2SUMI, ENP2LIFI, ENP2WPRI, ENP2MANI, ENP2EQUI) and shows “Life Policy Deleted”.

5.3.4 Option 4 – Update (two-step)

  1. Inquire with 01IEND through LGIPOL01, and display the current data.
  2. A second RECEIVE MAP collects the edits.
  3. Set 01UEND, take the customer number from ENP2CNOI, reset the payment and broker fields, and link to LGUPOL01.
  4. A non-zero return code goes to NO_UPD with no rollback. On success the program shows “Life Policy Updated”.

5.3.5 Invalid Option

The program shows “Please enter a valid option”, sets ENP2OPTL = -1, and sends the map with CURSOR.

6. Error Handling

6.1 Return Code Convention

After every LINK, each program tests CA_RETURN_CODE:

  • 0 means success.
  • Any value above 0 means failure and sends control to an error routine.
  • 70 has a special meaning on add. It means the customer does not exist.

6.2 Error Routines and Messages

Routine Trigger Motor Message (ERP1FLDO) Endowment Message (ERP2FLDO)
NO_DATA Inquire failed, or the inquiry step of update failed No data was returned. No data was returned.
NO_ADD Add failed, return code 70 Customer does not exist Customer does not exist
NO_ADD Add failed, any other code Error Adding Motor Policy Error Adding Life Policy
NO_UPD Update failed Error Updating Motor Policy Error Updating Life Policy
NO_DELETE Delete failed Error Deleting Motor Policy Error Deleting Life Policy
OTHERWISE Invalid option Please enter a valid option Please enter a valid option

Success messages:

Operation Motor Endowment
Add New Motor Policy Inserted New Life Policy Inserted
Update Motor Policy Updated Life Policy Updated
Delete Motor Policy Deleted Life Policy Deleted

6.3 ERROR_OUT

All error routines converge on ERROR_OUT, which does the following:

  1. Sends the map with the message already in the error field.
  2. Clears the map structure and the whole COMMAREA (COMM_AREA_RAW).
  3. Resets CA_REQUEST_ID, CA_RETURN_CODE, CA_CUSTOMER_NUM and CA_REQUEST_INITIALISER.
  4. Branches to ENDIT_STARTIT so the operator can retry from a clean state.
PLI 
NO_ADD:
   SELECT (CA_RETURN_CODE);
      WHEN (70)  ERP1FLDO = 'Customer does not exist';
      OTHERWISE  ERP1FLDO = 'Error Adding Motor Policy';
   END;
   GO TO ERROR_OUT;

6.4 Transactional Integrity

Operation Rollback issued by menu program
Add Yes, EXEC CICS SYNCPOINT ROLLBACK
Delete Yes, EXEC CICS SYNCPOINT ROLLBACK
Inquire No
Update No

6.5 Known Gaps

  • There are no RESP or RESP2 checks, and no HANDLE CONDITION for PGMIDERR on LINK. Other CICS conditions fall to the default CICS action, normally an abend.
  • There are no PL/I ON-units and no explicit ABEND calls.
  • Apart from the option field, the menu programs do no field validation, so customer number, dates and amounts are validated in the back-end programs.
  • Return codes are tested only for being greater than zero. Only code 70 on add is interpreted.

7.5 Invalid Option

For option 9 on either menu, the program sets “Please enter a valid option”, sets the option length field to -1 so the cursor lands on the option field, sends the map with CURSOR, and returns with the program’s own transaction ID (SSP1 or SSP2).

8. Dependencies and Constraints

8.1 Runtime Dependencies

Dependency Description
CICS PL/I translator and runtime Needed for Options(Main,Reentrant), DFHEIPTR and EXEC CICS.
Transactions SSP1 and SSP2 Must be defined to CICS and associated with LGTESTP1 and LGTESTP2.
Mapset SSMAP Must be installed. The maps SSMAPP1 and SSMAPP2 are used.
Programs LGIPOL01, LGAPOL01, LGUPOL01, LGDPOL01 Must be defined as CICS programs. They must honour the 32,500-byte COMMAREA contract and set CA_RETURN_CODE.

8.2 Key Constraints

  • Every LINK uses COMMAREA(COMM_AREA) LENGTH(32500).
  • The request ID values in section 2.3 are fixed contracts with the back-end programs.
  • CA_PAYMENT, CA_BROKERID and CA_BROKERSREF are always reset to 0, 0 and blank on add and update.
  • HANDLE AID and HANDLE CONDITION must run before RECEIVE MAP.
  • Update must follow the inquire, then receive, then update sequence.
  • After the SELECT in both programs there is an unconditional EXEC CICS RETURN. It is unreachable in normal flow, because each branch jumps away first.
