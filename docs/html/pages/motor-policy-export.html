Motor Policy Export

1. Overview

LGMOTOUT is a batch (non-CICS) Enterprise PL/I program within the GenApp portfolio responsible for exporting motor insurance policy data. It extracts the full contents of the relational Db2 table GENASA1.MOTOR through a read-only database cursor (MOTOR_CSR) and writes each row as a fixed-length, 132-byte space-separated record to the sequential flat file MOTOROUT.

During execution, the program tracks the total number of successfully written records and issues a completion message displaying the final row count. It actively monitors for file open failures, database cursor open errors, fetch anomalies, and output transmission errors. Program termination status is communicated to the operating system or invoking batch job step via standard Language Environment return codes: 0 for successful completion, 8 for a database fetch error, and 12 for file open or cursor initialization failures.

2.1 Architecture Components

  • Batch JCL & Runtime Attachment: Initiates execution under standard batch facilities (such as IKJEFT01 or DSN RUN) with an authorized Db2 plan/package and allocated datasets.
  • LGMOTOUT Program Module: The core PL/I application program containing embedded SQL statements and file I/O operations.
  • Db2 Database Subsystem (GENASA1.MOTOR): The relational data store containing policyholder vehicle records, retrieved sequentially via read-only cursor operations.
  • Sequential Output Dataset (MOTOROUT): Fixed-block (FB), 132-byte record sequential dataset that stores formatted flat-file exports.
  • System Display / SYSOUT: Diagnostic and operational output destination receiving record counts and formatted error messages.

5. Program Components and Execution Logic

5.1 Main Procedure (LGMOTOUT)

The main procedure initializes control structures, registers the file open exception handler, opens the database cursor, and controls the extraction loop:

  1. Establishes the ON UNDEFINEDFILE(MOTOROUT) condition. If triggered during OPEN, it executes:
    PLI 
    DISPLAY('LGMOTOUT: OPEN MOTOROUT FAILED');
   CALL PLIRETC(12);
   STOP;
  2. Sets EM_SQLREQ = ' OPEN MOTOR-CSR ' and issues EXEC SQL OPEN MOTOR_CSR.
  3. If SQLCODE ^= 0, it assigns SQLCODE to EM_SQLRC, invokes WRITE_ERROR_MESSAGE, closes MOTOROUT, sets PLIRETC(12), and terminates via RETURN.
  4. Executes the fetch loop:
    PLI 
    DO WHILE (SQLCODE ^= 100 & SQLCODE >= 0);
      CALL FETCH_MOTOR_ROWS;
   END;
  5. Closes MOTOR_CSR and MOTOROUT, then displays the summary record count:
    PLI 
    DISPLAY('LGMOTOUT: ROWS WRITTEN=' || WS_ROW_COUNT);

5.2 Fetch Routine (FETCH_MOTOR_ROWS)

Performs single-row fetches from the cursor into host storage and handles return status:

  1. Updates EM_SQLREQ = ' FETCH MOTOR-CSR '.
  2. Executes:
    PLI 
    EXEC SQL FETCH MOTOR_CSR INTO :WS_MOTOR_HV;
  3. Evaluates SQLCODE using a SELECT construct:
    • WHEN (0): Calls WRITE_MOTOR_ROW.
    • WHEN (100): End of data reached; no action taken, allowing loop termination.
    • OTHERWISE: Captures SQLCODE into EM_SQLRC, calls WRITE_ERROR_MESSAGE, and invokes CALL PLIRETC(8). A negative SQLCODE breaks the loop condition.

5.3 Write Routine (WRITE_MOTOR_ROW)

Formats host data and writes fixed-block records:

  1. Transfers binary and character values from WS_MOTOR_HV to WS_MOTOR_LINE, applying zero-padded picture transformations to numeric fields.
  2. Transfers the formatted structure to MOTOROUT_REC via STRING(WS_MOTOR_LINE).
  3. Establishes an ON TRANSMIT(MOTOROUT) handler that clears MOTOROUT_OK = '0'B.
  4. Sets MOTOROUT_OK = '1'B and executes:
    PLI 
    WRITE FILE(MOTOROUT) FROM(MOTOROUT_REC);
  5. Evaluates write status:
    • If MOTOROUT_OK = '0'B: Displays 'LGMOTOUT: WRITE FAILED' and calls WRITE_ERROR_MESSAGE.
    • If MOTOROUT_OK = '1'B: Increments WS_ROW_COUNT by 1.

5.4 Error Handling Routine (WRITE_ERROR_MESSAGE)

Formats and displays diagnostic messages to SYSOUT:

  • Populates the ERROR_MSG structure (EM_DATE, EM_TIME, ' LGMOTOUT', EM_SQLREQ, ' SQLCODE=', EM_SQLRC).
  • Note: WS_DATE and WS_TIME remain unassigned (initialized to blanks), leaving the timestamp prefix blank in the output message.
  • Issues a DISPLAY statement containing the full concatenated string.

6. Dependencies and Runtime Constraints

6.1 Database and Runtime Dependencies

  • Db2 Table Authority: Requires SELECT authorization on GENASA1.MOTOR.
  • SQL Communication Area: Includes SQLCA to evaluate SQLCODE after each database interaction.
  • Batch Attachment: Executes under a standard Db2 batch plan/package (e.g., via IKJEFT01 / DSN RUN).
  • Language Environment: Requires standard IBM Enterprise PL/I runtime libraries supporting PLIRETC and condition handling.

6.2 File and Environment Constraints

  • DD Allocation: JCL must supply the MOTOROUT DD statement allocated with Fixed Block (FB) records and LRECL=132.
  • Capacity Constraint: The record counter WS_ROW_COUNT (PIC '999999999') supports a maximum export limit of 999,999,999 records.
  • Read-Only Cursor: Cursor MOTOR_CSR specifies FOR READ ONLY, precluding any positional UPDATE or DELETE operations.

6.3 Return Codes and Status Indicators

Return Code Condition Action Taken
0 Successful Completion All rows extracted and written; final row count displayed.
8 Db2 Fetch Failure Diagnostic message displayed with SQLCODE; closes files and exits.
12 File Open or Cursor Open Failure Diagnostic message displayed; terminates immediately or after closing open resources.
