Customer Update

The Customer Update function is an online CICS transaction process within the GenApp insurance application responsible for updating customer demographic, address, and contact details across both relational (Db2) and file-based (VSAM) data tiers.

This business capability is executed via a coordinated chain of three specialized PL/I modules:

  1. LGUCUS01: The entry orchestrator program that performs initial runtime checks, request discriminator validation, and delegates backend processing.
  2. LGUCDB01: The relational database backend program that executes SQL updates against the Db2 CUSTOMER table and then propagates changes downstream.
  3. LGUCVS01: The file-control backend program that reads and rewrites the customer record in the KSDSCUST VSAM KSDS file to ensure cross-tier synchronization.

1. Overview

When a client or frontend interface issues an update request, the transaction provides a 32,500-byte communication area (LGCMAREA) containing updated customer details (such as names, date of birth, address elements, phone numbers, and email) along with the unique 10-digit customer identification number.

The multi-tier update chain executes in the following sequence:

  • Orchestration (LGUCUS01): Validates the presence of the COMMAREA and ensures the request discriminator (CA_REQUEST_ID) matches '01UCUS'. It resets operational counters and passes the payload to LGUCDB01 via EXEC CICS LINK.
  • Relational Persistence (LGUCDB01): Converts the numeric customer identifier to a 31-bit host integer, performs an SQL UPDATE against the CUSTOMER table, and evaluates the SQLCODE. Regardless of Db2 record existence or errors, it forwards the update payload (first 225 bytes) to LGUCVS01.
  • VSAM Synchronization (LGUCVS01): Issues an EXEC CICS READ ... UPDATE on VSAM KSDS file KSDSCUST using the customer number as the record key to acquire an exclusive lock, followed immediately by an EXEC CICS REWRITE to overwrite the existing record.
  • Diagnostic Logging (LGSTSQ): If an abnormal condition or fatal failure occurs anywhere along the pipeline, standardized error messages and up to 90 bytes of the commarea snapshot are transmitted via EXEC CICS LINK to the centralized logging queue subprogram LGSTSQ.

4. Component Deep Dive

4.1. Orchestration Layer: LGUCUS01

LGUCUS01 serves as the initial boundary program and facade for the customer update workflow. It implements defensive guardrails before dispatching work to backend database modules.

4.1.1. Core Logic & Guardrail Validation

  • Commarea Presence: Verifies EIBCALEN > 0. If no commarea is passed, it formats a diagnostic record, links to LGSTSQ, and abends immediately with code LGCA.
  • Request Type Identification: Confirms CA_REQUEST_ID = '01UCUS'. If any other discriminator is received, it sets CA_RETURN_CODE = '99' and returns immediately without invoking database programs.
  • State Initialization: Initializes CA_RETURN_CODE = '00', clears CA_NUM_POLICIES = 0, and captures CICS execution metadata (EIBTRNID, EIBTRMID, EIBTASKN).
  • Delegation: Transmits the 32,500-byte COMM_AREA structure directly to LGUCDB01 via EXEC CICS LINK.

4.2. Relational Database Layer: LGUCDB01

LGUCDB01 provides data access to the Db2 relational backend, managing SQL error conditions and orchestrating synchronization with the VSAM file tier.

4.2.1. Db2 SQL Processing

The module maps commarea fields to host variables, converting CA_CUSTOMER_NUM into a fixed binary 31-bit integer (DB2_CUSTOMERNUM_INT).

SQL 
EXEC SQL 
    UPDATE CUSTOMER
    SET FIRSTNAME    = :CA_FIRST_NAME,
        LASTNAME     = :CA_LAST_NAME,
        DATEOFBIRTH  = :CA_DOB,
        HOUSENAME    = :CA_HOUSE_NAME,
        HOUSENUMBER  = :CA_HOUSE_NUM,
        POSTCODE     = :CA_POSTCODE,
        PHONEMOBILE  = :CA_PHONE_MOBILE,
        PHONEHOME    = :CA_PHONE_HOME,
        EMAILADDRESS = :CA_EMAIL_ADDRESS
    WHERE 
        CUSTOMERNUMBER = :DB2_CUSTOMERNUM_INT;

4.2.2. Db2 Status Codes and Handling

  • SQLCODE = 0: Update successful; CA_RETURN_CODE remains '00'.
  • SQLCODE = 100: Record not found; sets CA_RETURN_CODE = '01'. No system log is created as this is treated as a business condition.
  • SQLCODE < 0 or other non-zero: Relational system error; sets CA_RETURN_CODE = '90', populates EM_SQLREQ = ' UPDATE CUST ', and logs diagnostics to LGSTSQ.
  • Downstream Call: Issues EXEC CICS LINK PROGRAM('LGUCVS01') LENGTH(225) across all SQL outcomes.

4.3. File Synchronization Layer: LGUCVS01

LGUCVS01 maintains parity between the relational table and the legacy KSDSCUST VSAM KSDS dataset.

4.3.1. VSAM Read for Update and Rewrite Sequence

The program executes a two-step CICS File Control sequence:

  1. Acquire Update Lock:

    PLI 
    EXEC CICS READ 
        FILE('KSDSCUST') 
        INTO(WS_CUSTOMER_AREA) 
        RIDFLD(CA_CUSTOMER_NUM) 
        KEYLENGTH(10) 
        UPDATE 
        RESP(WS_RESP) 
        RESP2(WS_RESP2);

    If WS_RESP != DFHRESP(NORMAL), it sets CA_RETURN_CODE = '81', links to LGSTSQ, and abends with code LGV1.

  2. Rewrite Record:

    PLI 
    EXEC CICS REWRITE 
        FILE('KSDSCUST') 
        FROM(CA_CUSTOMER_NUM) 
        LENGTH(WS_COMMAREA_LENF) 
        RESP(WS_RESP) 
        RESP2(WS_RESP2);

    If WS_RESP != DFHRESP(NORMAL), it sets CA_RETURN_CODE = '82', links to LGSTSQ, and abends with code LGV2.

5. Data Structures and Entity Mappings

5.1. Communication Area Layout (LGCMAREA)

The inter-program communication area (COMM_AREA) spans 32,500 bytes and encapsulates both header controls and customer attributes.

Field Name Type / Picture Length (Bytes) Description
CA_REQUEST_ID CHAR(6) 6 Operation identifier ('01UCUS' for customer update)
CA_RETURN_CODE PIC '99' 2 2-digit outcome return code
CA_CUSTOMER_NUM PIC '9999999999' 10 Unique numeric customer key
CA_FIRST_NAME CHAR(10) 10 Customer given name
CA_LAST_NAME CHAR(20) 20 Customer family name
CA_DOB CHAR(10) 10 Date of birth (YYYY-MM-DD)
CA_HOUSE_NAME CHAR(20) 20 Residential house name
CA_HOUSE_NUM CHAR(4) 4 Residential house number
CA_POSTCODE CHAR(8) 8 Postal / ZIP code
CA_NUM_POLICIES PIC '999' 3 Number of associated policies (reset to 000)
CA_PHONE_MOBILE CHAR(20) 20 Mobile telephone contact
CA_PHONE_HOME CHAR(20) 20 Home landline contact
CA_EMAIL_ADDRESS CHAR(100) 100 Customer electronic mail address
CA_POLICY_DATA CHAR(32267) 32267 Trailing policy payload slice / overlay

5.2. Entity-Relationship Model

The customer update pipeline synchronizes data between relational tables, VSAM indexed files, and transient logging queues.

6. Error Handling and Return Codes

The Customer Update pipeline utilizes return codes placed in CA_RETURN_CODE alongside explicit CICS ABEND codes when transactional backout or administrative intervention is required.

6.1. Return Code Reference Matrix

Return Code Issuing Program Severity Meaning / Condition Subsequent Action
'00' LGUCUS01 / LGUCDB01 Success Customer updated successfully in Db2 and VSAM Control returned to caller
'01' LGUCDB01 Warning Customer record not found in Db2 (SQLCODE = 100) Proceeds to VSAM update; returns '01'
'81' LGUCVS01 Fatal VSAM READ UPDATE failed (RESP != NORMAL) Logs to LGSTSQ, abends with LGV1
'82' LGUCVS01 Fatal VSAM REWRITE failed (RESP != NORMAL) Logs to LGSTSQ, abends with LGV2
'90' LGUCDB01 Error Db2 relational error (SQLCODE < 0 or unexpected) Logs to LGSTSQ, proceeds to VSAM sync
'99' LGUCUS01 Rejection Invalid request identifier (CA_REQUEST_ID != '01UCUS') Immediate return to caller

6.2. CICS Abend Code Summary

Abend Code Issuing Program Dump Mode Trigger Condition
LGCA LGUCUS01 / LGUCDB01 NODUMP Missing input communication area (EIBCALEN = 0)
LGV1 LGUCVS01 NODUMP Non-zero CICS response code during VSAM READ ... UPDATE
LGV2 LGUCVS01 NODUMP Non-zero CICS response code during VSAM REWRITE

6.3. Diagnostic Logging Routine (WRITE_ERROR_MESSAGE)

All three programs implement a consistent diagnostic logging mechanism:

  1. Captures absolute time using EXEC CICS ASKTIME and formats it into MMDDYYYY and HH:MM:SS using EXEC CICS FORMATTIME.
  2. Assembles the structured ERROR_MSG record containing the timestamp, calling program ID, customer number, and error codes (SQLCODE or RESP/RESP2).
  3. Dispatches ERROR_MSG to transient/temporary queues via EXEC CICS LINK PROGRAM('LGSTSQ').
  4. If EIBCALEN > 0, it extracts up to 90 bytes of the commarea (LEFT(COMM_AREA_RAW, 90)), formats it with prefix 'COMMAREA=', and sends a second log entry to LGSTSQ.

7. Execution Examples

7.1. Example 1: Successful End-to-End Customer Update

A client submits an update request with valid customer demographic changes.

Input Data

TEXT 
CA_REQUEST_ID     = '01UCUS'
CA_CUSTOMER_NUM   = '0000000123'
CA_FIRST_NAME     = 'John'
CA_LAST_NAME      = 'Smith'
CA_DOB            = '1980-05-12'
CA_HOUSE_NAME     = 'Willow Oaks'
CA_HOUSE_NUM      = '42'
CA_POSTCODE       = 'AB1 2CD'
CA_PHONE_MOBILE   = '07700900123'
CA_PHONE_HOME     = '01962811234'
CA_EMAIL_ADDRESS  = 'john.smith@example.com'
CA_NUM_POLICIES   = '005'

Processing Steps

  1. LGUCUS01 verifies EIBCALEN > 0 and CA_REQUEST_ID == '01UCUS'. It clears CA_NUM_POLICIES to 000, sets CA_RETURN_CODE = '00', and links to LGUCDB01.
  2. LGUCDB01 executes the SQL UPDATE for customer 123. The update matches 1 row and returns SQLCODE = 0.
  3. LGUCDB01 links to LGUCVS01 passing the updated customer buffer (225 bytes).
  4. LGUCVS01 issues READ FILE('KSDSCUST') UPDATE for key 0000000123 (returns NORMAL), followed by REWRITE FILE('KSDSCUST') (returns NORMAL).
  5. Control flows back up the chain to the caller.

Outcome

  • CA_RETURN_CODE = '00'
  • CA_NUM_POLICIES = '000'
  • Both Db2 CUSTOMER table and VSAM KSDSCUST file reflect the updated address, phone, and contact details.

7.2. Example 2: Non-Existent Customer (Db2 SQLCODE 100)

A client attempts to update a customer ID that does not exist in the database.

Input Data

TEXT 
CA_REQUEST_ID     = '01UCUS'
CA_CUSTOMER_NUM   = '0000009999'
CA_FIRST_NAME     = 'Bob'
CA_LAST_NAME      = 'Jones'

Processing Steps

  1. LGUCUS01 validates input and links to LGUCDB01.
  2. LGUCDB01 issues the SQL UPDATE where CUSTOMERNUMBER = 9999. No row is found; Db2 returns SQLCODE = 100.
  3. LGUCDB01 intercepts SQLCODE = 100 and assigns CA_RETURN_CODE = '01'. No diagnostic log is generated.
  4. LGUCDB01 continues its execution and links to LGUCVS01.
  5. LGUCVS01 attempts to locate key 0000009999 in KSDSCUST. The READ UPDATE returns a non-normal response.
  6. LGUCVS01 sets CA_RETURN_CODE = '81', links to LGSTSQ to log the failure, and terminates task execution with ABEND LGV1.

Outcome

  • CA_RETURN_CODE = '81'
  • Diagnostic log created via LGSTSQ containing error context for customer 0000009999.
  • Transaction terminates with abend LGV1 (NODUMP).

7.3. Example 3: Missing Communication Area (EIBCALEN = 0)

The program is invoked directly by a transaction without supplying a commarea payload.

Processing Steps

  1. LGUCUS01 evaluates EIBCALEN on entry and detects a length of 0.
  2. Sets EM_MSG_TEXT = ' NO COMMAREA RECEIVED'.
  3. Links to LGSTSQ with the timestamped error block.
  4. Executes EXEC CICS ABEND ABCODE('LGCA') NODUMP.

Outcome

  • Transaction abends immediately with LGCA.
  • No database or VSAM update operations are initiated.
