Shared Error and Message Logging (LGSTSQ)

1. Overview

LGSTSQ is the common logging utility of the GENAPP insurance application. It is a PL/I CICS program (LGSTSQ: Proc(COMM_AREA_PTR) Options(Main)). Other programs call it to record diagnostic and error text. An operator can also start it from a terminal.

For each request it builds one log record. The record is the originating CICS SYSID, a blank separator, and up to 90 bytes of message text. It writes that record to two places:

  • CSMT: the standard CICS transient data queue (TDQ).
  • A temporary storage queue (TSQ): GENAERRS by default, or GENAnnnn when the message starts with a Q=nnnn prefix.

The orchestrator programs (for example LGIPOL01), the Db2 programs (for example LGICDB01) and the VSAM program (LGACVS01) all call it with EXEC CICS LINK. The caller passes a message in the COMMAREA. When a terminal started the task, LGSTSQ also sends a one-byte text screen. The screen erases the display and unlocks the keyboard. This confirms the message was logged.

1.1 Key Characteristics

Characteristic Behaviour
Role Shared error and message logger for GENAPP
Invocation EXEC CICS LINK from programs, or a transaction started from a terminal
Destinations TDQ CSMT and TSQ GENAERRS or GENAnnnn
Record layout 4-byte SYSID, 1-byte blank, 90-byte message (95 bytes maximum)
Error policy Never abends the caller. Every CICS response is captured but never tested.
Dependencies CICS only. No Db2, no VSAM, no copybooks, no other programs.

2. System Architecture

2.1 Component View

3. Inputs and Invocation Modes

LGSTSQ decides where its message comes from by asking CICS which program, if any, invoked it.

3.1 CICS Task Context (ASSIGN)

Four EXEC CICS ASSIGN commands run first. Each stores its RESP in WS_RESP.

Field ASSIGN option Use
WRITE_MSG_SYSID (4 chars) SYSID Prefix identifying the source region on every record
WS_INVOKEPROG (8 chars) INVOKINGPROG Decides between COMMAREA input and terminal input
WS_STARTCODE (2 chars) STARTCODE Collected but never used
WS_PRINSYSID (4 chars) PRINSYSID Collected but never used

3.2 Mode 1: Program-to-Program Call (Flag C)

When WS_INVOKEPROG is not blank, another program linked to LGSTSQ.

  • COMMA_DATA (90 characters) is copied into WRITE_MSG_MSG.
  • WS_RECV_LEN is set to EIBCALEN.
  • No terminal output is produced.

3.3 Mode 2: Terminal-Started Transaction (Flag R)

When WS_INVOKEPROG is blank, a user started the transaction at a terminal.

  • EXEC CICS RECEIVE INTO(WS_RECV) reads the typed input.
  • WS_RECV_TRANID (5 characters) is dropped from the logged text.
  • WS_RECV_DATA (74 characters) is copied into WRITE_MSG_MSG.
  • WS_RECV_LEN is reduced by 5 to remove the transaction ID.
graph TD START[LGSTSQ entry] --> ASG[ASSIGN INVOKINGPROG] ASG --> Q{Invoking program
blank?} Q -- No --> C1[WS_FLAG = C] C1 --> C2[WRITE_MSG_MSG = COMMA_DATA] C2 --> C3[WS_RECV_LEN = EIBCALEN] Q -- Yes --> R1[RECEIVE INTO WS_RECV] R1 --> R2[WS_FLAG = R] R2 --> R3[WRITE_MSG_MSG = WS_RECV_DATA] R3 --> R4[WS_RECV_LEN = WS_RECV_LEN - 5] C3 --> NEXT[Queue selection] R4 --> NEXT

3.4 Input Summary

Input Size Source Notes
COMM_AREA_PTR Pointer Caller Addresses the COMMA structure
COMMA_DATA 90 chars Caller COMMAREA Primary message when called by a program
EIBCALEN Halfword EIB Initial length for program-called requests

4. Log Record Format and Length Arithmetic

4.1 Record Layout

WRITE_MSG has a fixed 95-byte layout.

graph LR A[WRITE_MSG_SYSID
4 bytes
CICS SYSID] --> B[FILLER_X
1 byte
blank] --> C[WRITE_MSG_MSG
90 bytes
message text]

There is no timestamp, program name or severity in this record. Callers put those into the message text. The date, time and program name are part of the caller’s ERROR_MSG structure.

4.2 Defaults Set at Declaration

Field Initial value Meaning
WS_RECV_LEN 80 Default length, a FIXED BIN(15) halfword
STDQ_NAME 'CSMT' Fixed TD queue name. It is never changed.
FILLER_X blank Separator between SYSID and text. It is also the one-byte terminal confirmation text.
MSGEND “Transaction ended” Declared but never used

WRITE_MSG and WS_RECV are cleared to blanks at entry. Unused positions are blank, not garbage.

4.3 Length Calculation

WS_RECV_LEN is adjusted in stages. The final value is the LENGTH used on both queue writes.

Step Adjustment Condition
Initial value EIBCALEN Program-called (C)
Initial value Received length, then −5 for the transaction ID Terminal-started (R)
Prefix removal −7 Message starts with Q=
Header allowance +5 (4-byte SYSID plus 1-byte filler) Always

5. Processing Logic

5.1 End-to-End Sequence

sequenceDiagram participant Caller as Caller or Terminal participant L as LGSTSQ participant CICS as CICS Runtime participant TD as TDQ CSMT participant TS as TSQ GENAxxxx Caller->>L: LINK with COMMAREA, or transaction input L->>L: Clear WRITE_MSG and WS_RECV L->>CICS: ASSIGN SYSID, STARTCODE, PRINSYSID, INVOKINGPROG CICS-->>L: Task context alt Invoking program not blank L->>L: Flag C, copy COMMA_DATA, length = EIBCALEN else Invoking program blank L->>CICS: RECEIVE INTO(WS_RECV) CICS-->>L: Terminal input L->>L: Flag R, copy WS_RECV_DATA, length - 5 end L->>L: Select queue name, strip Q= prefix if present L->>L: Length + 5 L->>TD: WRITEQ TD QUEUE(CSMT) L->>TS: WRITEQ TS QUEUE(STSQ) NOSUSPEND opt Flag R L->>Caller: SEND TEXT FROM(FILLER_X) LENGTH(1) ERASE WAIT FREEKB end L->>CICS: RETURN

5.2 Fixed Ordering

The processing order is fixed:

  1. Clear work areas.
  2. Issue the four ASSIGN commands.
  3. Acquire the message.
  4. Resolve the queue name.
  5. Adjust the length.
  6. Write to the TDQ.
  7. Write to the TSQ.
  8. Send the terminal confirmation, only for flag R.
  9. Return.

The TDQ write always comes before the TSQ write. EXEC CICS RETURN is the only exit, and it ends the task after one message is logged. There are no loops.

6. Queue Routing

6.1 Default and Custom Queue Names

The TSQ name is built from a fixed GENA prefix and a four-character suffix.

Message begins with TSQ used
Anything other than Q= GENAERRS (default)
Q=nnnn GENAnnnn

The TDQ is always CSMT.

graph TD A[STSQ = GENAERRS] --> B{First 2 chars
of message = Q= ?} B -- No --> Z[Keep text and queue] B -- Yes --> C[Copy chars 3 to 6
into STSQ positions 5 to 8] C --> D[TEMPO = text from position 8] D --> E[WRITE_MSG_MSG = TEMPO
prefix stripped] E --> F[WS_RECV_LEN = WS_RECV_LEN - 7] F --> Z

6.2 Prefix Handling Logic

This is the queue-selection logic, shown in PL/I:

PLI 
STSQ = 'GENAERRS';
IF SUBSTR(WRITE_MSG_MSG,1,2) = 'Q=' THEN DO;
   SUBSTR(STSQ,5,4) = SUBSTR(WRITE_MSG_MSG,3,4);
   TEMPO            = SUBSTR(WRITE_MSG_MSG,8,83);
   WRITE_MSG_MSG    = TEMPO;
   WS_RECV_LEN      = WS_RECV_LEN - 7;
END;

6.3 Prefix Rules

  • The prefix is matched case-sensitively and only at the start of the message. A Q= anywhere else is treated as ordinary text.
  • The prefix occupies 7 bytes: Q=, four suffix characters, and one following character. The text is taken from position 8 onward.
  • The nnnn suffix is not validated. It is not checked for numeric content, for blanks, or for whether the resulting queue name is valid.
  • SUBSTR(WRITE_MSG_MSG,8,83) runs to position 90, so the tail of TEMPO is blank-padded.

7. Outputs

7.1 Transient Data Queue Write

PLI 
EXEC CICS WRITEQ TD QUEUE(STDQ_NAME)
                    FROM(WRITE_MSG)
                    LENGTH(WS_RECV_LEN)
                    RESP(WS_RESP);

The record goes to CSMT, the standard CICS message destination. There is no NOSUSPEND, so default CICS behaviour applies.

7.2 Temporary Storage Queue Write

PLI 
EXEC CICS WRITEQ TS QUEUE(STSQ)
                    FROM(WRITE_MSG)
                    LENGTH(WS_RECV_LEN)
                    NOSUSPEND
                    RESP(WS_RESP);

The record is the same as the TDQ record. NOSUSPEND means the task does not wait if storage is unavailable. The request is ignored, and the only trace is the RESP stored in WS_RESP.

7.3 Terminal Confirmation

This runs only when WS_FLAG = 'R':

PLI 
EXEC CICS SEND TEXT FROM(FILLER_X) LENGTH(1)
                    TERMINAL WAIT ERASE FREEKB;

It sends a single blank character. This clears the screen and unlocks the keyboard. No message text is shown. Program callers (WS_FLAG = 'C') get no terminal output.

7.4 Task Termination

EXEC CICS RETURN ends the task or returns to the caller. LGSTSQ has no explicit return value and does not modify the COMMAREA.

7.5 Output Summary

Output Destination Condition
Log record TDQ CSMT Always
Log record TSQ GENAERRS or GENAnnnn Always
One-byte blank screen Terminal Only when started from a terminal

8. Integration with Calling Programs

8.1 Calling Pattern

The calling programs follow the same pattern. Each builds a fixed ERROR_MSG structure and links to LGSTSQ with the structure as the COMMAREA:

PLI 
EXEC CICS LINK PROGRAM('LGSTSQ')
               COMMAREA(ERROR_MSG)
               LENGTH(STG(ERROR_MSG));

If a COMMAREA was present, the caller then sends a second record:

PLI 
IF EIBCALEN > 0 THEN DO;
   IF EIBCALEN < 91 THEN
      CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN);
   ELSE
      CA_DATA = LEFT(COMM_AREA_RAW, 90);
   EXEC CICS LINK PROGRAM('LGSTSQ')
                  COMMAREA(CA_ERROR_MSG)
                  LENGTH(STG(CA_ERROR_MSG));
END;

The second record is prefixed with COMMAREA= and carries at most 90 bytes of the caller’s COMMAREA, so support staff can reconstruct the failing request. ERROR_MSG is 90 bytes (10-character date, 8-character time, 9-character program identifier, 63-character variable text). This matches the 90-byte COMMA_DATA that LGSTSQ reads.

8.2 Known Callers

Caller Role When it logs Message content
LGIPOL01 Policy inquiry orchestrator EIBCALEN = 0, then abends with LGCA Date, time, LGIPOL01, NO COMMAREA RECEIVED
LGICDB01 Db2 customer inquiry EIBCALEN = 0, or an unexpected SQLCODE (return code 90) Date, time, LGICDB01, customer number, SQL request, SQLCODE
LGACVS01 VSAM customer add Failed WRITE FILE('KSDSCUST') (return code 80), then abends with LGV0 Date, time, LGACVS01, customer number, RESP, RESP2

8.4 Caller Behaviour After Logging

LGSTSQ never abends. What happens next is decided by the caller.

Caller After logging
LGICDB01 Returns to its caller with CA_RETURN_CODE = '90'. The LGCA abend applies only to the zero-length COMMAREA case.
LGACVS01 Abends the task with LGV0 and no dump
LGIPOL01 Abends the task with LGCA and no dump

9. Error Handling

9.1 Response Capture Without Evaluation

Every ASSIGN, RECEIVE and WRITEQ command specifies RESP(WS_RESP).

  • CICS does not abend the task on a failed command, so the program always runs to the end.
  • WS_RESP is overwritten by each command and never tested. Failures are silent.
  • There are no HANDLE CONDITION, HANDLE ABEND or PL/I ON-units.
  • SEND TEXT has no RESP option. A failure there would follow default CICS condition handling, which is an abend. The program has no handler for it.

9.2 Failure Behaviour by Step

Failed step Effect
ASSIGN The related field keeps its initial blank value. For INVOKINGPROG, this means the program takes the terminal path.
RECEIVE WS_RECV stays blank, so a blank message is still logged using a length derived from WS_RECV_LEN.
WRITEQ TD The TSQ write still runs.
WRITEQ TS (for example no storage) The terminal confirmation still runs.

9.3 Defaulting and Fallbacks

  • The TSQ defaults to GENAERRS before the prefix check.
  • The TDQ is a hard-coded constant, CSMT.
  • Work areas are blank-initialised, so missing data produces blanks and not garbage.
  • There are no retries, alternate destinations or retry loops.

9.4 Resource Contention

  • The TSQ write uses NOSUSPEND. The task never waits for storage, and the TS log entry is dropped if none is available.
  • The TDQ write has no equivalent option.

9.5 Validation Gaps

  • EIBCALEN is not checked, so a zero-length COMMAREA is not rejected. The LGCA abend convention used by other programs does not apply here.
  • The COMMAREA pointer is not validated. The COMMA structure is based on COMM_AREA_PTR, so the COMMAREA is assumed to be at least 90 bytes.
  • The computed WS_RECV_LEN is not guarded against negative or out-of-range values.
  • The Q=nnnn suffix is not validated.

10. Constraints

10.1 Size Limits

Item Limit
Message text 90 bytes (COMMA_DATA is CHAR(90))
Terminal input 79 bytes received (5-byte transaction ID plus 74-byte data); 74 bytes logged
Log record 95 bytes (4 + 1 + 90)
WS_RECV_LEN FIXED BIN(15), a halfword
Q= prefix 7 bytes removed

10.2 Behavioural Constraints

  • Every record carries the originating SYSID, so the source region can always be identified.
  • One message is logged per task. The program runs once and returns.
  • The terminal confirmation is sent only after both queue writes.
  • WS_STARTCODE, WS_PRINSYSID and MSGEND are declared but have no effect on processing.

11.1 Runtime Dependencies

LGSTSQ has no %INCLUDE members, copybooks, database access, file I/O or calls to other programs.

11.2 Build and Definition Prerequisites

  • It must be compiled with the CICS translator or integrated CICS translation for PL/I. This provides the EXEC CICS handling and the EIB.
  • It must be defined to CICS as a PROGRAM resource.
  • It needs a TRANSACTION definition if it is to be started from a terminal.

12. Examples

12.1 Example 1: Program-to-Program LINK (Default Queue)

Scenario: LGIPDB01 hits a Db2 error and links to LGSTSQ, passing 90 bytes of message text.

Field Value
COMMA_DATA 'LGIPDB01 DB2 SELECT FAILED SQLCODE=-803 ' (padded to 90)
WS_INVOKEPROG 'LGIPDB01'
CICS SYSID 'IYK3'

Steps:

  1. INVOKINGPROG is non-blank, so WS_FLAG = 'C'. The message is copied from COMMA_DATA, and WS_RECV_LEN = EIBCALEN = 90.
  2. The message starts with LG, not Q=, so STSQ stays GENAERRS.
  3. WS_RECV_LEN becomes 95 after adding 5 for the SYSID and filler.
  4. The record is written to TDQ CSMT and TSQ GENAERRS at length 95.
  5. There is no terminal output, and the program returns.

Result:

TEXT 
CSMT:      IYK3 LGIPDB01 DB2 SELECT FAILED SQLCODE=-803...
GENAERRS:  IYK3 LGIPDB01 DB2 SELECT FAILED SQLCODE=-803...

12.2 Example 2: Terminal Message with Q= Prefix (Custom Queue)

Scenario: A support operator types a message at a terminal. The message selects a custom queue.

Field Value
Terminal input 'LGSQ Q=AUDTAUDIT POLICY REJECTED FOR CUST 0000000042' (transaction ID 'LGSQ ' plus data)
WS_INVOKEPROG blank
WS_RECV_LEN after RECEIVE 55
CICS SYSID 'IYK3'

Steps:

  1. INVOKINGPROG is blank, so the program issues RECEIVE. It sets WS_FLAG = 'R', copies WS_RECV_DATA into WRITE_MSG_MSG, and reduces WS_RECV_LEN by 5, giving 50.
  2. The message starts with Q=:
    • SUBSTR(STSQ,5,4) takes 'AUDT', so STSQ = 'GENAAUDT'.
    • The prefix is stripped through TEMPO.
    • WS_RECV_LEN is reduced by 7, giving 43.
  3. WS_RECV_LEN is increased by 5, giving 48.
  4. The record is written to TDQ CSMT and TSQ GENAAUDT at length 48.
  5. SEND TEXT ... ERASE FREEKB clears the screen and unlocks the keyboard, then the program returns.

Result:

TEXT 
CSMT:      IYK3 AUDIT POLICY REJECTED FOR CUST 0000000042...
GENAAUDT:  IYK3 AUDIT POLICY REJECTED FOR CUST 0000000042...
Terminal:  Screen erased, keyboard unlocked

In this example the text after the four suffix characters begins with AUDIT.... The program removes a fixed 7 bytes and takes the text from position 8. The byte after nnnn is consumed as part of the prefix. Operators and callers should therefore put a single separator character, such as a blank, between Q=nnnn and the message text. Otherwise the first character of the text is lost.

12.3 Example 3: Caller-Side Message (LGACVS01 Duplicate Key)

A failed VSAM write in LGACVS01 produces two LINKs to LGSTSQ. The first carries the error structure:

TEXT 
05152024   10:32:45 LGACVS01 CNUM=0000000123 Write file KSDSCUST RESP=   +14 RESP2=    +0

The second carries the COMMAREA snapshot, up to 90 bytes:

TEXT 
COMMAREA=01ACUS800000000123Sally     Jones ...

Each message is written to CSMT and GENAERRS. The caller then abends with LGV0.

13. Operational Notes

  • Monitoring: Operators can read CSMT for a chronological stream of all application messages. They can read GENAERRS or a GENAnnnn queue for application-specific entries, using standard CICS TS queue browsing.
  • Queue segregation: Callers or operators can route messages to a dedicated queue by prefixing the text with Q=nnnn plus a separator character.
  • Silent failure: Because RESP codes are never tested, a missing queue definition or full TS storage produces no visible error. Check queue definitions and TS storage if expected entries are missing.
  • Record content: Date, time, program name, customer and policy identifiers come entirely from the caller’s formatted message. LGSTSQ adds only the SYSID.
