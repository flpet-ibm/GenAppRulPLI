Customer Inquiry

1. Overview

The Customer Inquiry function of the General Insurance application (GenApp) is implemented by three cooperating CICS PL/I programs:

Program Role
LGICUS01 Business-logic entry point. Validates the request and routes it.
LGICDB01 Db2 retrieval layer. Reads the customer from the CUSTOMER table.
LGICVS01 Customer number provider. Returns a valid, existing customer number from the KSDSCUST VSAM file, using the range held in the GENACNTL temporary storage queue.

A caller passes a communication area (COMMAREA) containing a 10-digit customer number to LGICUS01. LGICUS01 checks that the COMMAREA is present and large enough, then checks a control temporary storage queue (GENAWMQC) to choose a route. Normally it links to LGICDB01, which runs a singleton SELECT against Db2 and fills the name, date of birth, address, phone and email fields in the COMMAREA. The result is reported in CA_RETURN_CODE.

LGICVS01 supports the inquiry by supplying a customer number that exists. It picks a pseudo-random number within the range stored in GENACNTL. It then does a GTEQ read of KSDSCUST to find the nearest real key. This is useful for testing, demonstration and other programs that need a valid customer number.

LGICUS01 and LGICDB01 form the inquiry chain. LGICVS01 is a separate service: it does not link to LGICUS01 or LGICDB01. Its output, a valid customer number, can be used as CA_CUSTOMER_NUM in an inquiry request.

2.2 Component Responsibilities

Component Type Responsibility
LGICUS01 CICS PL/I program (Options(Main)) Validates COMMAREA length, sets the return code, scans GENAWMQC and links to the retrieval program. It has no direct Db2, file or MQ calls.
LGICDB01 CICS PL/I program with embedded SQL Converts the customer number to a binary integer, runs a singleton SELECT on CUSTOMER and maps SQLCODE to a return code.
LGICVS01 CICS PL/I program Reads or initialises the GENACNTL range, generates a random key and reads KSDSCUST with GTEQ.
AAAAAAAA Placeholder program Alternate target when an MQHIT= record is found.
LGSTSQ CICS logging program Writes the formatted error message and a COMMAREA snapshot to the error queues.
GENAWMQC CICS TS queue Routing control queue read by LGICUS01.
GENACNTL CICS TS queue Holds the eyecatcher, LOW CUSTOMER= and HIGH CUSTOMER= records used by LGICVS01.
KSDSCUST VSAM KSDS Customer master file with a 10-byte key and 225-byte records.
CUSTOMER Db2 table Source of the customer details returned to the caller.

3. Customer Lookup Flow

3.1 End-to-End Sequence

sequenceDiagram participant Caller participant CUS as LGICUS01 participant MQC as TSQ GENAWMQC participant DB as LGICDB01 participant Db2 as Db2 CUSTOMER participant LOG as LGSTSQ Caller->>CUS: LINK with COMMAREA, CA_CUSTOMER_NUM alt EIBCALEN = 0 CUS->>LOG: ERROR_MSG - NO COMMAREA RECEIVED CUS-->>Caller: ABEND LGCA NODUMP else EIBCALEN < 90 CUS-->>Caller: CA_RETURN_CODE = 98 else valid COMMAREA CUS->>MQC: READQ TS ITEM 1, then NEXT MQC-->>CUS: records or non-normal response CUS->>DB: LINK COMMAREA 32500 bytes DB->>Db2: SELECT WHERE CUSTOMERNUMBER = host var Db2-->>DB: row and SQLCODE DB-->>CUS: customer fields and CA_RETURN_CODE CUS-->>Caller: EXEC CICS RETURN with COMMAREA end

3.2 LGICUS01: Validation and Initialisation

On entry, LGICUS01 receives COMM_AREA_PTR. It copies the transaction ID, terminal ID and task number from the EIB into the WS_HEADER diagnostic structure, which starts with the eyecatcher LGICUS01------WS. It then does the following, in order:

  1. No COMMAREA (EIBCALEN = 0). It sets EM_MSG_TEXT to ' NO COMMAREA RECEIVED', calls WRITE_ERROR_MESSAGE and abends with LGCA (NODUMP).
  2. Defaults. It sets CA_RETURN_CODE to '00' and CA_NUM_POLICIES to 0. It saves EIBCALEN and the COMMAREA address.
  3. Minimum length. The required length is WS_CUSTOMER_LEN (72) + WS_CA_HEADERTRAILER_LEN (18) = 90 bytes. If EIBCALEN is smaller, it sets CA_RETURN_CODE to '98' and returns without a lookup. Nothing is logged.
  4. Diagnostics. It copies CA_CUSTOMER_NUM into EM_CUSNUM so any later error message carries the customer number.
  5. Lookup. It calls GET_CUSTOMER_INFO and then issues EXEC CICS RETURN.
graph TD A([Start LGICUS01]) --> B[Capture EIBTRNID EIBTRMID EIBTASKN] B --> C{EIBCALEN = 0} C -- Yes --> D[WRITE_ERROR_MESSAGE
ABEND LGCA NODUMP] C -- No --> E[CA_RETURN_CODE = 00
CA_NUM_POLICIES = 0] E --> F{EIBCALEN less than 90} F -- Yes --> G[CA_RETURN_CODE = 98
EXEC CICS RETURN] F -- No --> H[Move CA_CUSTOMER_NUM to EM_CUSNUM] H --> I[GET_CUSTOMER_INFO] I --> J[EXEC CICS RETURN]

3.3 LGICUS01: Routing Through GENAWMQC

GET_CUSTOMER_INFO resets MQ_HIT to 0 and reads item 1 of the GENAWMQC queue into the 80-character MQ_READ_RECORD. If that read is NORMAL, it reads every following record with NEXT until the response is non-zero, normally ITEMERR at the end of the queue. Any record whose first six characters are MQHIT= sets MQ_HIT to 1. The loop does not stop at the first match.

The routing decision is:

MQ_HIT Target program
0 (default, also used if the queue is missing or empty) LGICDB01
1 AAAAAAAA

Condensed from the logic described above:

PLI 
MQ_HIT = 0;
EXEC CICS READQ TS QUEUE(MQ_CONTROL) ITEM(1)
          INTO(MQ_READ_RECORD) RESP(WS_RESP);
IF (WS_RESP = DFHRESP(NORMAL)) THEN DO;
   DO UNTIL (WS_RESP > 0);
      EXEC CICS READQ TS QUEUE(MQ_CONTROL) INTO(MQ_READ_RECORD)
                RESP(WS_RESP) NEXT;
      IF (WS_RESP = DFHRESP(NORMAL)) &
         (SUBSTR(MQ_READ_RECORD,1,6) = 'MQHIT=') THEN MQ_HIT = 1;
   END;
END;

IF (MQ_HIT = 0) THEN
   EXEC CICS LINK PROGRAM(LGICDB01) COMMAREA(COMM_AREA) LENGTH(32500);
ELSE
   EXEC CICS LINK PROGRAM('AAAAAAAA') COMMAREA(COMM_AREA) LENGTH(32500);

The queue reads use RESP, so a missing queue cannot abend the task. A missing queue is treated as “no hit”. The LINK commands have no RESP checking, so failures in the linked program go to CICS default handling. LGICUS01 also does not inspect the return code that LGICDB01 sets. The code and customer data pass straight back to the caller.

3.4 LGICDB01: Db2 Retrieval

LGICDB01 repeats the entry checks: COMMAREA present, return code '00', and the 90-byte minimum. It then converts CA_CUSTOMER_NUM to the FIXED BIN(31) host variable DB2_CUSTOMERNUMBER_INT and saves the customer number in EM_CUSNUM. GET_CUSTOMER_INFO sets the SQL request label to ' SELECT CUSTOMER'. It then runs a singleton SELECT with the predicate CUSTOMERNUMBER = :DB2_CUSTOMERNUMBER_INT.

4. Random Customer Number Service (LGICVS01)

4.1 Invocation Modes

LGICVS01 works out how it was started with EXEC CICS ASSIGN:

PLI 
EXEC CICS ASSIGN STARTCODE(WS_STARTCODE) RESP(WS_RESP);
EXEC CICS ASSIGN INVOKINGPROG(WS_INVOKEPROG) RESP(WS_RESP);
  • If SUBSTR(WS_STARTCODE,1,1) = 'D' or WS_INVOKEPROG is not blank, it was called by a program. WS_FLAG is set to 'C' (COMMAREA mode), and the length comes from EIBCALEN.
  • Otherwise it was started from a terminal. It does EXEC CICS RECEIVE, sets WS_FLAG to 'R', and reduces the received length by 5 for the transaction ID.

4.2 The GENACNTL Range Queue

The valid customer number range is shared through the GENACNTL TS queue. Access is serialised with ENQ and DEQ on the queue name.

Queue item Content Length written
Eyecatcher **** GENAPP CNTL 20
Low bound LOW CUSTOMER= + 10 digits 23
High bound HIGH CUSTOMER= + 10 digits 24

WS_CUST_LOW and WS_CUST_HIGH default to 1000001, and the three “must write” flags start as 'Y'. If item 1 reads normally, the eyecatcher flag is cleared. The program then loops over the remaining items until the response is greater than 0. LOW CUSTOMER and HIGH CUSTOMER records update the bounds and clear their flags. Any record still flagged 'Y' is then written with NOSUSPEND, so a missing queue is created with default values.

The record layout is mapped by a union:

PLI 
DCL 1  READ_MSG UNION,
      3 READ_MSG_MSG             CHAR(80) INIT(' '),
      3 *,
        5 *                      CHAR(13),
        5 READ_CUST_LOW          PIC '(10)9',
      3 *,
        5 *                      CHAR(14),
        5 READ_CUST_HIGH         PIC '(10)9';

The ENQ and DEQ pair:

PLI 
EXEC CICS ENQ RESOURCE(STSQ_NAME) LENGTH(STG(STSQ_NAME));
...
EXEC CICS DEQ RESOURCE(STSQ_NAME) LENGTH(STG(STSQ_NAME));

4.3 Random Selection and VSAM Read

After the queue is released, the program computes a pseudo-random number seeded by the task number:

PLI 
WS_RANDOM_NUMBER = FLOOR(RANDOM(EIBTASKN) * FLOAT(WS_CUST_HIGH - WS_CUST_LOW) + WS_CUST_LOW);

It uses this number as the key for a GTEQ read of KSDSCUST:

PLI 
EXEC CICS READ FILE('KSDSCUST')
          INTO(CA_AREA)
          LENGTH(F82)
          RIDFLD(WRITE_MSG_HIGH)
          KEYLENGTH(F10)
          RESP(WS_RESP)
          GTEQ;

If WS_RESP is NORMAL, WRITE_MSG_HIGH is replaced with the real CA_CUSTOMER_NUM. If the read fails, for example with NOTFND, the random number is returned unchanged. The caller can then receive a number that does not exist in the file.

WS_FLAG = R] D --> F[Defaults LOW = HIGH = 1000001

4.4 Output

In COMMAREA mode the result is returned in an 84-byte structure:

PLI 
COMMA_DATA_H    = WRITE_MSG_H;
COMMA_DATA_HIGH = WRITE_MSG_HIGH;
COMMA_DATA_FILL = (60)' ';

In terminal mode it is displayed as text:

PLI 
EXEC CICS SEND TEXT FROM(WRITE_MSG_H)
          WAIT
          ERASE
          TERMINAL
          LENGTH(24)
          FREEKB;

The 24-byte length covers the 14-character label HIGH CUSTOMER= and the adjacent 10-digit customer number.

6. Return Codes and Error Handling

6.1 Return Codes in the COMMAREA

CA_RETURN_CODE Set by Meaning
00 LGICUS01, LGICDB01 Success (SQLCODE 0).
01 LGICDB01 Customer not found (SQLCODE 100) or resource unavailable (SQLCODE -913).
90 LGICDB01 Unexpected Db2 error. The error is logged.
98 LGICUS01, LGICDB01 COMMAREA shorter than 90 bytes.

6.2 Error Handling Behaviour

  • No COMMAREA. LGICUS01 and LGICDB01 both log the error and abend with LGCA without a dump. This is the only abend path.
  • Short COMMAREA. The code '98' is returned and no error message is written, so the rejection leaves no diagnostic record.
  • Db2 errors. LGICDB01 sets '90', calls WRITE_ERROR_MESSAGE and returns. Unexpected conditions such as SQLCODE -811 (duplicate rows) or -305 (null column without an indicator variable) fall into this branch.
  • Error logging. WRITE_ERROR_MESSAGE gets the time with ASKTIME and formats it with FORMATTIME (MMDDYYYY). It links to LGSTSQ with ERROR_MSG. If EIBCALEN is above 0, it links a second time with CA_ERROR_MSG, which holds COMMAREA= and up to 90 bytes of the input.
  • Gaps. None of the LINK commands to LGSTSQ, LGICDB01 or AAAAAAAA check RESP. LGICUS01 does not check the downstream return code.
  • LGICVS01 fallbacks. A missing GENACNTL queue gets default records. A failed VSAM read keeps the random number. The ASSIGN, RECEIVE and WRITEQ responses are not checked.

7. Constraints and Operational Considerations

Area Constraint
COMMAREA size 32,500 bytes total. The minimum for an inquiry is 90 bytes (72 customer + 18 header/trailer).
Customer number CA_CUSTOMER_NUM is PIC '9999999999'. It is not validated for numeric content or existence by LGICUS01. It must fit FIXED BIN(31) for the Db2 key.
Routing Only the first 6 characters of each 80-character GENAWMQC record are compared, case-sensitively. One match anywhere in the queue is enough.
Db2 Host variable lengths must match the column lengths. No indicator variables are used. The CICS-Db2 attachment and execute authority on CUSTOMER are required.
Hard-coded names LGICDB01, AAAAAAAA, LGSTSQ, GENAWMQC, GENACNTL and KSDSCUST are fixed in the source.
Concurrency In LGICVS01, ENQ/DEQ covers only the GENACNTL read and initialisation. It does not cover the random selection or the VSAM read.
Default range If GENACNTL is absent, LOW = HIGH = 1000001, so the “random” number is always 1000001.
Random seed RANDOM(EIBTASKN) is seeded by the task number.
CICS resources The programs, KSDSCUST file, AAAAAAAA (if the alternate path is used) and LGSTSQ must be defined and available.
Build Compiled with SYSTEM(CICS) and PP(MACRO,CICS) and deployed as CICSLOAD.

8. Examples

8.1 Successful Inquiry via Db2

Input: EIBCALEN = 200, CA_CUSTOMER_NUM = 0000000001, and no MQHIT= record in GENAWMQC.

  1. LGICUS01 sets the return code to '00', and the length check passes.
  2. The queue scan finds no hit, so MQ_HIT stays 0.
  3. LGICUS01 links to LGICDB01, which converts the key to 1 and runs the SELECT. SQLCODE is 0.
Field Value
CA_RETURN_CODE 00
CA_FIRST_NAME Andrew
CA_LAST_NAME Pandy
CA_DOB 1950-07-11
CA_POSTCODE PO1 1AA
CA_EMAIL_ADDRESS a.pandy@example.com

8.2 Customer Not Found

Input: CA_CUSTOMER_NUM = 0000999999, and no matching row exists.

SQLCODE is +100, so CA_RETURN_CODE is '01'. The customer fields are not populated and no error message is written.

8.3 COMMAREA Too Short

Input: EIBCALEN = 50.

Since 50 < 90, LGICUS01 sets CA_RETURN_CODE to '98' and returns. There is no queue read, no LINK and no Db2 access.

8.4 Alternate Routing on an MQ Hit

Input: EIBCALEN = 32500, and GENAWMQC holds two records, the second starting with MQHIT=.

The scan sets MQ_HIT to 1 and continues to the end of the queue. LGICUS01 then links to AAAAAAAA with the same 32,500-byte COMMAREA instead of LGICDB01. CA_RETURN_CODE stays '00' unless the alternate program changes it.

8.5 Obtaining a Valid Customer Number (LGICVS01)

Input: LINK call. GENACNTL has LOW CUSTOMER=0000000001 and HIGH CUSTOMER=0000000100. KSDSCUST has keys 1, 5, 42 and 100. The random draw is 37.

The GTEQ read with key 0000000037 returns key 0000000042.

CODE 
COMMA_DATA_H    = "HIGH CUSTOMER="
COMMA_DATA_HIGH = 0000000042
COMMA_DATA_FILL = (60 blanks)

The caller can use 0000000042 as CA_CUSTOMER_NUM in the inquiry flow.

8.6 Terminal Start With No Queue

When the transaction is entered at a terminal and GENACNTL does not exist, the defaults (1000001) are used and the three queue records are created. The screen shows:

CODE 
HIGH CUSTOMER=0001000001

8.7 Random Key Not Found in VSAM

If the queue range is 2000000 to 2000500, the random draw is 2000600, and KSDSCUST has no key at or above it, the GTEQ read returns a non-normal response. The COMMAREA returns COMMA_DATA_HIGH = 2000600, the generated value, which may not exist in the file.
