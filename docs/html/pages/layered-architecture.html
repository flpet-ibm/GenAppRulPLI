Layered Architecture and Call Flow

This document provides a comprehensive technical reference for the layered architecture, inter-program linkage mechanisms, Communication Area (COMMAREA) standards, and end-to-end execution flows within the General Insurance (GenApp) application.

1. Overview

The GenApp core insurance processing platform is structured as an enterprise-grade, four-tier CICS application implemented in PL/I. The design separates user presentation, business logic orchestration, relational persistence (IBM Db2 for z/OS), and secondary record synchronization (VSAM KSDS / file storage).

All inter-layer communication is standardized using a 32,500-byte shared COMMAREA passed synchronously across programs via EXEC CICS LINK and maintained between terminal interactions through pseudo-conversational EXEC CICS RETURN TRANSID(...) COMMAREA(...) statements.

2. System Architecture and Component Layering

2.1 Four-Tier Architecture Model

  1. Presentation Layer (3270 BMS Screen Handlers): Programs named LGTESTxx manage interactive user dialogues using Basic Mapping Support (BMS). They execute pseudo-conversationally, intercept Attention Identifier (AID) keys (CLEAR, PF3), capture terminal inputs, perform data sanitization (e.g., null-to-blank translations and uppercase normalization), and invoke the business orchestrators via EXEC CICS LINK.
  2. Business Logic Orchestration Layer: Programs named LGxxUS01 (Customer domain) and LGxxOL01 (Policy domain) serve as transaction coordinators. They contain no embedded SQL. They enforce COMMAREA length minimums, validate transaction request IDs, evaluate external routing switches (such as TS Queue flags or IBM Operational Decision Manager rules), and dispatch calls to the backend database tier.
  3. Relational Persistence Layer (Db2): Programs named LGxxDB01 contain embedded SQL (EXEC SQL). They manage row-level locking via positioned cursors (SELECT ... FOR UPDATE OF), enforce optimistic concurrency validation comparing record timestamps (LASTCHANGED), execute CRUD operations on Db2 tables (CUSTOMER, POLICY, ENDOWMENT, HOUSE, MOTOR, COMMERCIAL, CLAIM), and manage transactional recovery (EXEC CICS SYNCPOINT ROLLBACK).
  4. File Synchronization Layer (VSAM): Programs named LGxxVS01 are synchronously invoked by the Db2 backend programs after successful SQL execution. They replicate updates to legacy VSAM Key-Sequenced Data Sets (KSDS) to guarantee strict consistency across data stores.

3. Communication Area (COMMAREA) Standards & Interface Contracts

3.1 32,500-Byte Unified Buffer (LGCMAREA)

Inter-program data transfer across all four tiers relies on a unified COMMAREA structure defined in copybook LGCMAREA.inc. It consists of an 18-byte standard header followed by a 32,482-byte variable request area mapped as a union overlay:

3.3 Return Code Protocols (CA_RETURN_CODE)

CA_RETURN_CODE is a 2-digit picture field (PIC '99') governed by specific architectural meanings across layers:

Code Meaning Originating Layer Handled Behavior
'00' Success All Layers Continue execution, map returned payload to screen, commit task.
'01' Not Found Db2 Backend (LGxxDB01) SQLCODE = 100 on Fetch/Update. Presentation displays "No data was returned."
'02' Stale Timestamp (Optimistic Lock) Db2 Backend (LGUPDB01) Timestamp collision (CA_LASTCHANGED $\neq$ DB2_LASTCHANGED). Aborts update.
'70' Customer Does Not Exist Add Backend / Orchestrator Specific check on policy addition. Screen displays "Customer does not exist".
'90' Database / System Error Db2 Backend (LGxxDB01) Non-zero SQLCODE (e.g. -913 deadlock). Error logged to LGSTSQ, triggers rollback.
'98' COMMAREA Too Short Orchestrator (LGxxOL01, LGxxUS01) EIBCALEN below required length. Immediate return without backend invocation.
'99' Unsupported Request ID Orchestrator (LGxxOL01, LGxxUS01) CA_REQUEST_ID unrecognised. Rejects request before persistence execution.

5. Cross-Layer Transaction Control and Error Handling

5.1 Rollback and Consistency Protocols

To protect transactional integrity across heterogeneous resources (Db2 relational tables and VSAM files), explicit unit-of-work management is applied:

  1. Presentation Layer Rollbacks: If LGAPOL01 (Add) or LGDPOL01 (Delete) returns a non-zero CA_RETURN_CODE to LGTESTP1, LGTESTP3, or LGTESTP4, the presentation program issues an explicit EXEC CICS SYNCPOINT ROLLBACK before repainting the screen. This undoes any uncommitted changes across Db2 and VSAM.
  2. Backend Db2 Rollbacks: In LGUPDB01, if the positioned update or the subsequent timestamp read-back SELECT LASTCHANGED fails, the program issues an explicit EXEC CICS SYNCPOINT ROLLBACK, sets CA_RETURN_CODE = '90', and logs the error.
  3. Optimistic Locking Guard: Stale data updates are blocked without initiating a rollback by comparing timestamps before executing any SQL modifications:
PL1 
/* Optimistic Concurrency Control in LGUPDB01 */
IF ( CA_LASTCHANGED = DB2_LASTCHANGED ) THEN DO;
    /* Proceed to policy subtype update & core policy update */
    CALL UPDATE_HOUSE_DB2_INFO;
    IF ( CA_RETURN_CODE = '00' ) THEN DO;
        EXEC SQL
          UPDATE POLICY
            SET ISSUEDATE        = :CA_ISSUE_DATE,
                EXPIRYDATE       = :CA_EXPIRY_DATE,
                LASTCHANGED      = CURRENT TIMESTAMP,
                BROKERID         = :DB2_BROKERID_INT,
                BROKERSREFERENCE = :CA_BROKERSREF
            WHERE CURRENT OF POLICY_CURSOR;
    END;
END;
ELSE DO;
    /* Record modified concurrently by another task */
    CA_RETURN_CODE = '02';
END;

5.2 Centralized Diagnostic Logging (LGSTSQ)

All orchestrator and persistence programs standardize error logging through the utility module LGSTSQ. When an unrecoverable or database exception occurs, the calling program formats a structured ERROR_MSG and an auxiliary CA_ERROR_MSG containing a snippet of the input COMMAREA (up to 90 bytes), linking to LGSTSQ to write records to a CICS Transient Data Queue (TDQ) or Temporary Storage Queue (TSQ).

Date, Time, Program, SQLCODE, Keys] C --> D[EXEC CICS LINK PROGRAM 'LGSTSQ'
Commarea ERROR_MSG] D --> E{EIBCALEN > 0?} E -- Yes --> F[Extract up to 90 bytes of COMM_AREA_RAW] F --> G[EXEC CICS LINK PROGRAM 'LGSTSQ'
Commarea CA_ERROR_MSG] E -- No --> H[Skip Payload Dump] G --> I[Write to CICS TDQ / TSQ CSMT] H --> I
PL1 
/* Standardized Error Logging Routine in LGxxOL01 / LGxxDB01 */
WRITE_ERROR_MESSAGE: PROCEDURE;
    EXEC CICS ASKTIME ABSTIME(WS_ABSTIME);
    EXEC CICS FORMATTIME ABSTIME(WS_ABSTIME)
              MMDDYYYY(WS_DATE)
              TIME(WS_TIME);

    EM_DATE = WS_DATE;
    EM_TIME = WS_TIME;

    EXEC CICS LINK PROGRAM('LGSTSQ')
              COMMAREA(ERROR_MSG)
              LENGTH(STG(ERROR_MSG));

    IF ( EIBCALEN > 0 ) THEN DO;
        IF ( EIBCALEN < 91 ) THEN
            CA_DATA = LEFT(COMM_AREA_RAW, EIBCALEN);
        ELSE
            CA_DATA = LEFT(COMM_AREA_RAW, 90);

        EXEC CICS LINK PROGRAM('LGSTSQ')
                  COMMAREA(CA_ERROR_MSG)
                  LENGTH(STG(ERROR_MSG));
    END;
END WRITE_ERROR_MESSAGE;

5.3 Exception and Condition Trapping

The application enforces strict entry guardrails across all program procedures:

  • Missing COMMAREA Trap (EIBCALEN = 0): Any orchestrator or backend module invoked with EIBCALEN = 0 sets the diagnostic message ' NO COMMAREA RECEIVED', logs the event via WRITE_ERROR_MESSAGE, and issues EXEC CICS ABEND ABCODE('LGCA') NODUMP.
  • BMS Exception Handling: Presentation programs establish EXEC CICS HANDLE AID for CLEAR (invoking CLEARIT to send MAPONLY) and PF3 (invoking ENDIT to terminate the session). EXEC CICS HANDLE CONDITION MAPFAIL(ENDIT) prevents task abends when screens are submitted with no data.
  • Queue Concurrency Serialization: In LGTESTC1, simultaneous additions of customer records are serialized using EXEC CICS ENQ RESOURCE('GENACNTL') and EXEC CICS DEQ RESOURCE('GENACNTL') around the high-water mark read/rewrite loop.
